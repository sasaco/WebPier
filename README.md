# WebPier 直接基礎・上部工反力・線路方向／直角方向荷重の計算

`pre/input.json`を読み、0500の地盤ばね、0600の上部工反力・橋脚自重、0610の線路方向荷重、0620の直角方向荷重、0710の地震時線路方向荷重、0720の地震時線路直角方向荷重と組合せ係数を計算してPDFと結果JSONを作成します。計算はPython、計算書の組版はGridLayoutPdf、PDF描画はそのReportLabバックエンドを使用します。実行時にExcelや元のxls/PDFは不要です。

対象は`input.xls!計算スタートボタン_Click`からの0500直接基礎計算、0600上部工反力計算、0610線路方向荷重、0620直角方向荷重と、0710地震時線路方向荷重・0720地震時線路直角方向荷重です。方向別の骨組条件・荷重成分・基本ケース・元表の組合せ係数を含みます。0620は`.claude/docs/Example橋脚2`の非地震時17基本ケース・15定義ケース・16組合せ・8抽出、0710は地震時8基本ケース・1組合せ、0720は地震時9基本ケース・1組合せを扱います。**構造解析による組合せ応答、部材の断面照査、寸法・配筋の最適化は未実装**です。既定入力はサンプル条件で、WebPier固有資料へ未置換です。

```powershell
uv run --project "." --locked python "./run_design.py"
```

入力を編集して再計算する場合:

```powershell
uv run --project "." --locked python "./run_design.py" --overwrite
```

選択段階と必要な依存段階の入力検証・計算を終えてから、選択したPDF/JSONを生成し、成果物をまとめて公開します。更新に失敗した場合は旧成果物を復元し、その実行で新規作成した出力を削除します。復元まで失敗した場合は退避ファイルを残し、その場所を通知します。同名ディレクトリやシンボリックリンク、入力と出力の同一パスは拒否します。`--stage 0500`は上部構造を要求せず、`--stage 0600`は排除土の単位体積重量の参照元として先頭地層の湿潤単位体積重量だけを要求し、支持層やEdは要求しません。`--stage 0610`は0500と0600を内部で各1回計算するため両方の入力が必要ですが、0610のPDF/JSONとFrameWeb入力・付帯JSONの4ファイルを公開します。選択しない段階の成果物には触れません。入力は一度だけ読み込み、その同じバイト列のSHA256を全ての計算結果に記録します。

### 地震時の線路方向荷重

`--stage 0710`は、現在入力から0500→0600→0610を内部で各1回計算し、その実行内の0610結果を使います。保存済み0610成果物や参考PDFを要求せず、空の出力先にも0710のPDF/JSONだけを生成できます。0610を経由するため、非地震時側の入力・材料・ケースの検証条件も満たす必要があります。0710用のFrameWeb入力は生成しません。

節の順序は「10.1 検討モデル」「10.2 作用の計算」「10.3 作用の組合せ」です。`.claude/docs/Example橋脚2`の`08_線路.pdf`の1ページ目に対応する現在入力の地震時骨組図と、`10_線路(耐震).pdf`の8・12ページに対応する作用・ケースを含みます。内容に応じて改ページし、10 - 1から連番を付けます。ばね記号・数値・表は表示せず、固定端や非線形支持モデルも追加しません。

地震時骨組図には、耐震資料の1～5ページに従い柱下端の0.010 m微小部材を追加します。H4区間の下端0.010 mを分割するため全高は変わりません。現在入力では4.900 mを4.890 m＋0.010 mに分割し、7節点・6部材になります。節点番号・要素番号は上から下へそれぞれ1から連番とし、微小部材は節点4―5間の要素4になります。桁受けがある入力も高さ順に採番し、役割と接続参照を同時に更新します。拡大詳細は表示しません。H4が0.010 m以下、または座標精度上この区間を区別できない場合は明示エラーとします。微小部材の原本種別は非線形ですが、非線形構成則・解析パラメータ・他部材の剛域化は追加しません。

桁・橋脚自重の慣性力はKh=1.00、列車慣性力は線路方向のKh=0.20を適用済みの値で保持します。固定・増分・限定増分の8基本ケースと、全係数1の1組合せを定義します。平水位の揚圧力Wpの符号は保持し、方向「上」を併記します。この組合せ表から増分解析や部材照査は実行しません。

### 線路・線路直角方向のJRSNAP入力

`--jrsnap`を明示すると、同じ実行で読み込んだ入力と0500・対象方向の地震時計算結果からJRSNAP **5.2-L03**用のNDUと付帯JSONを生成します。`--stage 0710`は`post/線路方向.ndu`と`post/線路方向.ndu.provenance.json`、`--stage 0720`は`post/線路直角方向.ndu`と`post/線路直角方向.ndu.provenance.json`を対象とし、それぞれPDF/JSONと合わせて4ファイルを一括公開します。単独実行で他方向のNDUやFrameWebは変更しません。`--stage all`では両方向を含む20ファイルを一括公開します。他の単独stageとの併用はエラーです。指定しない場合は従来の出力数を維持し、既存NDUには触れません。

```powershell
uv run --project "." --locked python "./run_design.py" --stage 0710 --jrsnap --overwrite
uv run --project "." --locked python "./run_design.py" --stage 0720 --jrsnap --overwrite
uv run --project "." --locked python "./run_design.py" --stage all --jrsnap --overwrite
```

GridLayoutPdfは`pyproject.toml`に記載したローカルパスから導入します。ライブラリのソースを更新した場合は、同じversion番号でもインストール済みの内容が自動で置き換わるとは限らないため、次を実行します。現在のlockには描画に必要なPillow依存も含まれています。

```powershell
uv sync --project "." --locked --reinstall-package gridlayoutpdf
```

入力画面の「計算・印刷」には線路方向と線路直角方向の設定表があり、それぞれ次の4項目を入力します。「両方向のJRSNAP入力ファイルも出力」を選ぶと、通常の全帳票計算とともに両方向を出力します。チェックは起動時OFFです。未入力の欄は空欄のまま表示し、見本値や他方向の値を自動補完しません。編集した値だけを入力JSONへ保存します。旧入力でも通常の帳票計算は引き続き利用できます。

| 入力項目 | JSONキー（方向別設定内） | 範囲 |
|---|---|---|
| 部材係数 γb（Vcd） | `shear_factor_vcd` | 0より大きく99.99以下 |
| 部材係数 γb（Vsd） | `shear_factor_vsd` | 0より大きく99.99以下 |
| 部材係数 γb（Vdd） | `shear_factor_vdd` | 0より大きく99.99以下 |
| 粗骨材最大寸法 Dmax | `aggregate_max_mm` | 0.1〜999999 mm、実数 |

線路方向は`jrsnap_longitudinal`、線路直角方向は`jrsnap_transverse`に独立して保存します。CLIの単独出力ではその方向の4項目だけを必須とし、両方向のall出力では両方を検証します。

今回のWebPier入力には、ユーザー指定により両方向へ見本の初期値 **Vcd=2.0、Vsd=1.3、Vdd=1.8、Dmax=25 mm** を設定しています。これらは編集できる入力値として保存し、exporterの固定値・未入力時の補完値にはしません。

NDUでは柱下端0.010 mをM-θ部材、その他の部材を剛域とし、基礎の並進ばねと非線形回転ばねを設定します。0710/0720の帳票図・計算モデルにはこの解析用設定を書き戻しません。断面・配筋・基礎ばね・荷重は対象方向の入力と計算結果を使います。Dfとγ2は0500の表層・支持層と対象方向の平水位から自動導出し、出典、各区間長、丸め前値と採用値を専用付帯JSONに残します。対応する地盤条件は一つの表層と支持層、左右同じ土被り、基礎底面が支持層上面、`0 < hw2 < Df`です。未対応の地盤・材料・配筋条件や必須入力の不足は、公開前にエラーとして扱います。

手動配筋は、生成元の基本入力（basis）が現在入力と一致し、実際のバー配置も基本入力の自動配置と一致する場合に対応します。手動で移動したバー配置は、NDUの主筋段数・ピッチへの代表化が未定義のため拒否します。着目方向の主筋集合は全配筋の先頭・末尾各N段と芯位置・径・本数・材質が一致することを要し、側面筋が主筋より外側にある配置、主筋段間への割込み、同一段への追加混入はv1では拒否します。現在のWebPier配筋は対応範囲です。

見本`.claude/docs/Example橋脚2/08_線路.pdf`の28ページの手順を用い、`Df = H6 + H5 + min(df1, df2)`、`γ2 = ((Df − hw2) × γwet + hw2 × γsub) / Df`とします。γwet・γsubは表層の湿潤・水中単位体積重量です。Dfと0500表層厚の差を1e-9 m以内で照合し、γ2のNDU採用値だけをExcel ROUND互換で小数第1位へ丸めます。現在のWebPierでは`Df = 4.7 m`、`γ2 = (2.0 × 18 + 2.7 × 8) / 4.7 = 12.255319… kN/m³`から`12.3 kN/m³`を採用します。

`--post-dir`の既定・指定方法はFrameWebと共通です。NDUはCP932/CRLFで決定的に生成します。`--overwrite`は生成済みNDUへの手編集も置換します。入力・プログラム・候補・出力先が生成中に変わった場合は公開を止め、公開中の失敗では既存の退避・復元処理を適用します。GUIで先に保存した入力は、成果物の公開失敗でも保存済みのままです。

方向別の付帯JSONは入力全バイトのSHA、0500と対象方向0710/0720の全計算辞書のcanonical SHA、対象方向PDF/JSON/NDUのSHA、profile・地盤導出・対応表と公開IDを記録します。`all`ではFrameWebの既存schema 2を変えず、両NDUと同じ公開IDで世代を照合します。通常生成にJRSNAPアプリは不要で、`app_read_verified`と`analysis_run`は常にfalseです。初回のアプリ読込・再保存の確認は別の受入記録で扱い、アプリが保存し直したバイトを正式NDUに差し替えません。両方向を同時に受け入れる場合は、同じ入力世代の独立期待値とアプリ往復で両方を確認してから公開します。NDT出力、構造解析の実行、応答・耐震安全性の照査はこの機能の対象外です。

### 地震時の線路直角方向荷重

`--stage 0720`は、現在入力から0500→0600→正規0620を内部で各1回計算し、同じ実行の0600反力と0620の固定作用・骨組を使用します。0610・0710の計算、保存済み結果JSON、参照PDFは不要です。`--jrsnap`未指定時は空の出力先にも0720のPDF/JSONだけを生成し、他帳票とpostは変更しません。正規0620を経由するため、その非地震時側の入力・部位材料・ケースの検証条件も満たす必要があります。0720用FrameWeb入力は生成しません。

節の順序は「11.1 検討モデル」「11.2 作用の計算」「11.3 作用の組合せ」で、11 - 1から連番を付けます。`.claude/docs/Example橋脚2`の`09_直角.pdf`の骨組と`11_直角(耐震).pdf`の作用・組合せを現在入力で再構成します。ばね記号・数値・表と柱下端の拡大図は表示しません。全有効支承、非ゼロH1、異なるはり下・柱強度を表示し、内容に応じてページを増やします。支承行を打ち切ることや、文字を縮小して固定ページ数へ収めることはありません。

上部形状の高さは各側のh1+h2、桁慣性力の等価重心高はhsで、別の量です。同じ上部座標は共有し、異なる高さは両側の節点・寸法を保持し、ゼロ高さは梁天端へ統合します。上部形状部材へ自重を加算しません。柱下端は既存H4の0.010 mを分割し、全節点・要素を上から連番にします。現在入力では8節点・7要素、全高13.050 m、橋脚本体10.300 m、上部2.750 m、H4は4.890 m＋0.010 mです。微小部材は節点5―6間の要素5です。H4が0.010 m以下、または座標精度で分割を区別できない条件は入力エラーです。

列車鉛直荷重は0600の地震時反力に下り=L1、上り=L2の各側・支承の分担率を一度だけ適用し、負反力とC側固有アームを保持します。総Nは丸め前行和を2桁、総Mは2桁に丸めた各行Mの和です。EQ1はKh=1.00、EQLは直角方向Kh=0.30適用済みの0600値で、係数を再乗算しません。EQ1/EQLは梁天端の等価H/Mであり、上部形状節点へ移して高さによるモーメントを再加算しません。

自重慣性力EQ2はKh=1.00とし、はり上・下・柱の分布強度、H1の等価H/M、基礎重心の集中力を区別します。基礎は0600の実重量と排除土重量を使用し、非矩形基礎を外接矩形の体積へ置換しません。現在入力のシェルター分は既存D1/D2/S2とhsに集約されているため、未入力の個別内訳を復元しません。現在EQ1のH=9090 kNと原本9080 kNの差は入力由来で、原本合わせの調整は行いません。

9基本ケースのCase5は下り、Case6は上りとし、原本物理13ページの組合せ表を採用します。組合せ1は係数`[1,1,1,1,1,0,1,1,1]`、選択`1+2+3+4+5+7+8+9`、αf=1.0、ρm=1.0、方向右、地盤抵抗TYPE=1です。Wpは上向き表示でも符号を再反転しません。TYPEは組合せ条件として記録し、地盤抵抗計算・耐震応答解析・部材照査は行いません。

### 線路方向のFrameWeb入力

通常の0610/all計算で `post/frameWebForJS.json` も更新します。FEMPython / FrameWebforCSで開くファイルはこれです。PDFの読取りやExcel、FEMPythonの起動は日常の入力生成に必要ありません。

`--post-dir` でFrameWeb入力の出力先を指定できます。省略時は、通常の `./output` に対して `./post`、別の `--output-dir` に対してはその配下の `post` を使います。検証用の別出力先から本番postを更新しません。

```powershell
uv run --project "." --locked python "./run_design.py" --stage 0610 --output-dir "案件/output" --post-dir "案件/post" --overwrite
```

基本荷重1～20に、列車・衝撃の用途別ケース21～28を加えます。PDFの組合せ表は名目係数ですが、衝撃荷重には用途別係数が含まれ、列車モーメントは係数適用後に支点別で丸められます。補助ケースへ解決済み値を入れ、組合せでは係数1で参照することで二重適用と丸め差を避けます。水平荷重13～20だけを正負選択し、各荷重の長期／短期ばねを使った解析結果を重ね合わせます。現在は保存28荷重・28Define、16Combine・8Pickupで、荷重行のないWP3だけが解析時に省略されます。

使用性係数が0の場合も、解決済みのゼロ補助ケースを係数1で参照します。全零のCombine7とPickup4の応答を外部ソフトで保持するため、この条件に限り補助ケース21へ明示ゼロの節点荷重行を1件残します。微小荷重は加えず、名目係数0に非ゼロの解決済み作用があれば生成を止めます。付帯JSONには物理的なゼロケースと、解析で省略されるケースを分けて記録します。

節点・部材・荷重点は正規0610結果を保持します。基礎の剛域はExample由来の有限剛性（E=26,500,000 kN/m²、A=1,000 m²、Iz=1,000 m⁴）です。完全剛体拘束ではありません。対応と採用規約は付帯JSONへ記録します。出典ページには資料名も付け、Exampleの9～11頁とWebPierの6～8頁を区別します。

正式入力は正規計算の精度を保持し、headlessへ直接渡して検証します。現FrameWebforCSは多くの値をSingleで保持するため、GUIで保存し直すと回転ばね52,218,663が52,218,664、104,437,326が104,437,330になるなどの変換があります。GUI保存後のファイルに元の付帯JSONのSHA保証は適用できません。部材分布荷重の強度は解析投影時に小数2桁へ丸められるため、生成側でその精度境界を検査します。

### 直角方向のFrameWeb入力

通常の0620/all計算で `post/線路直角方向.json` を自動更新します。線路方向と同じ `--post-dir` の指定・既定値を使い、0620単独では線路方向の成果物を変更しません。正規0620の節点・部材・直角方向のIz/Krと点／分布荷重を使い、水平風は各部材のグローバルgx、鉛直分布はgyへ保存します。

17基本・15Defineを監査用に保持し、次のL+I補助を加えて、現入力では22荷重・19Define・16Combine・8Pickupを生成します。元PDFの240名目係数は付帯JSONで追跡できます。

| 補助load | Define | 用途 | Combine |
|---|---|---|---|
| 18 | 16 | 複線・終局最大のL+I | 1, 10 |
| 19 | 17 | 複線・終局一般のL+I | 2, 8, 11 |
| 20 | 18 | 複線・使用性のL+I | 5 |
| 21, 22 | 19 | 単線・使用性の上り／下りのL+I | 7, 15, 16 |

補助には用途別の解決済み値を使い、元L/I列を除いた組合せから係数1で参照します。使用性Iの245.3 kNや単線IMの272.73 kN mは基本Iへの単純な係数乗算では再現できません。上りL+上りI、下りL+下りIをそれぞれ一つの候補にすることで不正な上下混合を防ぎ、LFと風の正負選択は独立に残します。現入力の組合せ状態は37通りです。荷重成分が全て0の行は出力せず、ケース・DefineのIDは保持します。N=0でもMが非零なら荷重を保持します。

正規荷重の精度を維持し、Exampleの風の端数差・部分載荷・LF符号差をコピーしません。分布荷重のソルバー投影で正規作用に許容外の差が生じる入力は、位置・元値・投影値付きエラーで公開を止めます。抽出対象の組合せが全零となりFEMPythonの派生参照が成立しない入力（使用性係数0のCombine7等）も、具体的なエラーで停止して旧成果物を維持します。使用中Defineの一部候補だけが零の場合も、ソフトが零候補を省略して包絡を変えるため拒否します。架空の微小荷重は補いません。直角方向もGUI再保存ではSingle精度へ変わるため、別名で保存し、正式nativeと付帯JSONの組を保管してください。

### 公開世代の検証と中断時の復旧

各出力先と同じファイルシステム内で退避・置換し、通常の例外時は元の成果物へ復元します。複数ファイルがOS上で一瞬に切り替わる仕組みではありません。全native/PDF/計算JSONの後に付帯JSONを公開し、公開先の実bytesを再検証してから退避を片付けます。

新しい付帯JSONはschema2です。公開ジョブ共通の`publication_id`、全非sidecar成果物の役割・最終パス・SHAを持つ`artifact_manifest`、必要な付帯JSONの役割・パスを持つ`expected_sidecars`を記録します。allでは0710・0720のPDF/JSONを含む14件のmanifestと2件の付帯JSONを照合します。付帯JSON同士のSHAを循環参照しません。旧schema1は0610単独の確認だけに対応し、GUI全工程の成功判定には使えません。通常allを再実行すると両方向がschema2へ更新されます。

強制終了や復元失敗では、出力先ごとの`.webpier-*`内に`publication-pending`、`publication-journal.json`と退避ファイルを残します。中断時点によっては未完了マーカーだけが残ります。次の計算やGUI検証は未完了journalまたはマーカーを検出し、復旧場所を表示して停止します。他の計算結果を上書きする自動復旧はしません。計算プロセスが終了していることを確認し、journalが読める場合は各`destination`・`backup`・`had_original`を照合して旧成果物を復元するか、一式を別の場所へ保全してから再計算してください。成果物の公開・復元が完了してもマーカーを削除できなければ停止を維持します。マーカー除去後の一時ファイル削除だけが失敗した場合は警告となり、完了済みjournalは次回実行を妨げません。

左の入力表・選択行の条件を独立してスクロールでき、右の断面図と使用元（梁・フーチングは「基本配筋／指定位置」、柱は「自動配置／詳細修正」）は常に表示します。柱では、使用中の物理位置から線路・直角の段配置表と本数を確認できます。

- 「0500 入力チェック」で既存の直接基礎計算の入力条件を確認します。編集中の空欄や場所打ち杭のデータも保存可能です。このチェックは上部構造等の設計照査を行いません。計算・PDF生成は下記の「計算・印刷」または`run_design.py`から実行できます。
- 上部工反力の**A・D支点のD1・D2合計は「合計 (入力)」欄に入力し、入力JSONへ保存**します。0と負数も入力値として使用します。空欄や項目がない場合は、計算時にD1・D2それぞれA支点＝B支点、D支点＝C支点とします。**B・C支点のD1・D2・列車分担L1～L4合計は明細から自動更新**され、「合計 (自動)」欄は編集できません。表示上の集計では空欄と`-`を除外します。B・C支点の合計は入力JSONへ保存せず、旧JSONのB・C合計も読込時に除き、次の保存で反映します。元Excelの数式セル3項目も自動表示します（下記参照）。表示する単位は入力JSONの記載に従い、`null`の単位を推測して書き込みません。
- **雪荷重 2年確率・10年確率・30年確率**をD2と列車分担の間に入力できます。各確率についてB・C支点は支承明細の合計、A・D支点は直接入力とし、A・Dの空欄や項目欠落時だけ同じ確率のB・C合計を使用します。A・Dの明示的な0・負数も保持します。各確率を0600の「(1) 支点反力」「(2) 主桁反力」へ表示し、S2を使用性の支承鉛直荷重と両方向の桁地震荷重、S10を安全性・復旧性の列車併用、S30をLR単独へ連携します。D1/D2の独立集計は保持します。0610へS30鉛直・水平荷重と組合せ、0610・0620へS2込み桁地震荷重を渡します。

- 「開く」（Ctrl+O）、「上書き保存」（Ctrl+S）、「名前を付けて保存」（Ctrl+Shift+S）を利用できます。未保存の編集がある状態で開く・閉じる場合は、保存・破棄・キャンセルを選びます。
- 既存ファイルを保存する際は、同じフォルダに`input.json.YYYYMMDD-HHMMSS-ffffff.bak`の名前で変更前の全バイトを保存し、一時ファイルから置換します。バックアップが作れない場合は上書きしません。読込後に他のアプリが保存先を変更・削除した場合も上書きを止めます。別名保存するか、変更を確認して開き直してください。変更のない上書き保存ではファイルを更新しません。

PythonにTkがない場合はTkinterを含むPython環境を利用してください。Windowsの現在の`uv`環境ではTk 8.6で動作確認しています。

### 柱配筋の入力とWebPierの設定例

「鉄筋」で部材「柱」を選びます。断面は下部構造のW6・B6を参照し、Xは直角方向4500 mm、Yは線路方向2700 mm、原点は断面の左上です。断面図と方向別確認表は同じ物理配筋を表示し、確認表は直接編集しません。狭い画面では左側の入力欄をスクロールし、右側で図と方向別の表を確認できます。

`pre/input.json`の柱は、`.claude/docs/Example橋脚2/10_線路(耐震).pdf`と`11_直角(耐震).pdf`の物理6頁に合わせてあります。同じ設定を入力する手順は次のとおりです。

1. 共通条件を主筋・横補強筋ともSD390、コンクリート強度27 N/mm²、純かぶり70 mmにします。
2. 「帯鉄筋」で、旧入力なら「方向別の合計有効本数を入力する」を押します。現在断面の外帯筋径を22 mm、両方向の径を22 mm、間隔を150 mm、材質をSD390にし、合計有効本数を線路10・直角6とします。開始・終了位置は未指定のままにします。
3. 「基本配筋」で下表の2行を入力し、選択行の配置条件を設定します。**片面本数は一つの面の本数**です。線路の行は上下の面、直角の行は左右の面を配置します。

| 対向面 | 径・片面本数 | 芯かぶり | 配列方法 | 端部芯距離 | 配列ピッチ |
|---|---|---|---|---|---|
| 線路 | D32・29本 | 自動：108 mm | 両端＋中央ピッチ | 108 mm | 150 mm |
| 直角 | D19・9本 | 指定：102 mm | 中央ピッチ | 使用しない | 250 mm |

純かぶりは外帯筋の外面まで、芯かぶりは主筋の中心までの距離です。1段目のD32は70＋22＋32/2＝108 mmと自動計算します。D19は原本の102 mmを直接指定し、自動計算値101.5 mmを丸める規則は使いません。2段目以降の自動芯は、前段の径・芯位置と段間のあきから求めます。不足項目がある行は理由を表示し、完成した配置として扱いません。

端部芯距離は面内の側端面からの距離で、面に直交する芯かぶりとは別です。D32は両端108/4392 mm、内部27本が300～4200 mmの150 mm間隔となり、両端の間隔は192 mmです。D19は左右102/4398 mm、各面の9本が350～2350 mmの250 mm間隔です。D32が58本、D19が18本、合計76本となり、線路方向11行・直角方向31行の確認表を得ます。「等分」は指定区間を等分し、端部の鉄筋を含む／含めない条件を使用します。

新方式の帯筋10/6は外側・内側を含む方向別の合計有効本数です。5/3組や内側8/4本へ換算せず、帯筋の形状も推定しません。高さ区間は柱下端からの開始・終了位置で、空欄は未指定を意味します。旧帯筋行は保持され、「旧帯筋入力へ戻す」で明示的に切り替えられます。新旧の本数は加算しません。

「詳細修正」ではX・Y・径・材質を編集し、鉄筋を追加・削除できます。最初の実編集で完成した自動配置を詳細位置として記録します。以後、基本本数・ピッチ・材料・寸法を変更しても詳細位置は保持され、「基本条件の変更は未反映」と表示します。新しく記録する詳細位置の材質も固定し、既存の生成元情報がない指定XYは従来の材質継承を保ちます。

「再配置」では現在の詳細位置と新しい自動配置の図・本数・位置を比較し、「適用」で置き換えます。取消・生成エラーでは置き換えません。適用後も使用元は詳細修正のままです。「自動へ戻す」は比較後に自動配置へ切り替え、詳細位置を退避します。「詳細へ復帰」はその退避配置へ戻す操作で、新規の自動配置コピーとは区別します。現在寸法に収まらない退避配置は復帰できません。

新しい配列・帯筋・生成元情報を保存すると`鉄筋.version=2`になります。旧version1は従来の配置規則で読み、表示や無変更保存だけでは移行しません。version2で梁やフーチングを編集しても形式番号は維持します。柱の寸法・材料・配筋入力と配置確認が対象で、構造耐力・耐震照査、断面最適化、原本6頁形式の計算書出力はこの機能に含みません。

**支承位置 f は、起点側 L2 ＋ 終点側 L1 ＝ 起点側 f ＋ 終点側 f の関係で連動**します。片側の f を入力すると、反対側の f を「起点側 L2 ＋ 終点側 L1 − 入力した f」に更新します。L1・L2は変更しません。例えば L2＝0.575、L1＝0.375 のとき、片側 f＝0.4 と入力すると反対側 f＝0.55 になります。貼り付けにも連動し、元に戻す・やり直しは両方の f をまとめて戻します。同じ貼り付けで両方の f を変えた場合は起点側を優先します。空欄・不正な文字の入力中は反対側の値を保持します。L1・L2の編集だけでは f を変更しません。

### 車両別の制動・始動と雪荷重の組合せ

`上部構造.列車.車両名`が厳密に`EA-17`と一致する場合、制動は`(0.27＋1.00/Lv)×列車反力合計`、始動は`(0.25＋0.95/Lv)×列車反力合計`です。ここで反力合計は安全性単線表の当該桁両端の列車反力で、衝撃を含みません。それ以外の車両は制動`(0.20＋0.80/Lv×L)×軸重`、始動`(0.19＋0.76/Lv×L)×軸重`を使用します。Lは張出しを含む桁全長です。JSONの車両名欠落・null・空文字はEA-17以外として扱い、文字列以外は入力エラーにします。

基礎制動・始動値を小数2桁に丸めて大きい方を基礎Bとし、安全性・復旧性の既定組合せは`ROUND(ρu×γ, 2)`を採用します。例えばρu=1.23、γ=1.1なら1.35です。支承鉛直反力の列車項は`raw反力×複線分担率×(1＋衝撃係数)×有効係数`で算定し、0.1 kNへ丸めた衝撃表を倍率で割り戻しません。使用性の有効係数は`ρs×γ`です。入力ρuや列車・衝撃表そのものの精度は保持します。

EA-17の既定制動はρu込み基礎Bに有効係数/ρuを掛け、ρu=0なら寄与0とします。他車両は基礎Bへ有効係数を直接掛けます。側別の`復旧性制動係数`が明示された場合は、その値を丸めず直接適用します。このときだけEA-17も係数無しのraw反力合計から基礎Bを求めるため、ρu=0でも正の明示係数は有効です。係数0は制動寄与0、未設定・nullは従来の既定動作です。

雪荷重はS2＝2年、S10＝10年、S30＝30年確率として扱います。B/Cの欠落・null・0は計算上0、A/Dの欠落・nullは確率ごとにB/C合計へ補完し、明示0は補完しません。使用性0.8LRはD1＋D2＋S2、使用性1.0LRはD1＋D2＋複線L＋I＋S2です。安全性の支承鉛直荷重は両端とも1.1D1＋1.2D2に各ケースの複線列車項とS10を加え、復旧性はD1＋D2に列車項とS10を加えます。S30のLR単独は安全性1.1D1＋1.2D2＋S30、復旧性D1＋D2＋S30で、列車・衝撃を含みません。

### 丸めと移動荷重探索

セル計算は元の演算順と途中のExcel ROUNDを維持します。0600専用ROUNDは値を15有効桁へ正規化した後、0.5を絶対値の大きい側へ丸めます。例えば`639.9749999999999`は小数2桁で`639.98`、`639.9749999999`は`639.97`です。Microsoft Excelで正負の16境界値×小数0～3桁、128点を実測して照合しました。これは0600で使用する通常規模・桁数の検証であり、全数値範囲のExcel ROUND完全再現を保証するものではありません。0500の既存丸め処理は変更していません。

移動荷重は桁長・車両値と各加減乗除をVBAの`Single`へ逐次丸めます。候補軸は先頭から、7支点座標は6→0の順で探索します。載荷座標は元VBAの`Round(…, 3)`（偶数丸め）を使い、Excel ROUNDとは区別します。軸列を調べて座標が負になった時点でその候補の軸走査を終了し、全長以内の軸だけを採用します。左右桁の境界と同位置の軸はB/C寄与が大きい側に置き、同値ならC側に置きます。RB+RCがそれまでの最大値を**厳密に上回る**場合だけ更新し、同点は先に探索した候補を採ります。4反力それぞれの別々の最大値ではありません。正荷重がSingleで0へ消える場合や有効な最大反力位置がない場合は入力エラーにします。

桁継目の所属比較は、軸位置と継目をともに0.001 mの偶数丸めと`Single`変換でそろえます。例えば寸法の加算で20.000001907 mとなった継目と載荷位置20.000 mを同位置として扱います。右桁の腕長もSingle加算誤差の範囲内（継目座標の絶対値×2⁻²²以内）だけ同じ継目へそろえ、実際の半mm寸法は保持します。正の継目が丸めで原点0へ潰れる場合は元座標を保持し、原点の軸を誤って右桁へ載せません。元寸法・逐次Single演算・探索順と極小寸法の有効候補なしエラーは維持します。この境界処理は元VBAからの意図した修正であり、小数継目を含む全条件の旧反力との一致は保証しません。列車反力と車両横荷重の共通探索に適用します。

H1>0では方向別寸法a=BまたはWに対して中心`xp=(2*a2+a3-a1-a4+a5)/2`に基部と上端を設けます。H1断面はB3×W3の矩形で、A=`ROUND(B3*W3,3)`、線路方向I=`ROUND((1/12)*W3*B3^3,5)`、直角方向I=`ROUND((1/12)*B3*W3^3,5)`です。`sections.body`は従来の等価柱断面、`sections.parapet`はこの矩形です。正規結果の弾性部材は部位別材料を参照し、H1は柱を継承します。剛部材は`behavior=rigid`・断面/材料参照nullです。旧材料の完全再現は各方向のlegacy計算に残します。

H1=0ではH1節点・部材・断面を作りません。中心xp=0では基部を梁天端と共用し、水平剛アームを省きます。同じ座標の節点は優先順`[4,2,1,3,5,6,7,8]`で合流し、全roleと元行を保持します。H2/H3=0、hG=0または基礎天端でも長さ0部材を作らず、IDは欠番を許します。節点表示順や「節点4」の文字から支持先を推定せず、`support_node_id`を使用します。極小でも実偏心があれば別節点とし、表示桁では合流しません。正の高さが座標精度で消失する場合は入力エラーです。

**H1>0でB3またはW3が0、丸め後A/Iが0、非有限値の場合は0610・0620が入力パス付きエラーになります。** `all`も描画・公開前に失敗し、既存成果物を保持します。0600単独の0体積の扱いは従来どおりです。

部材追加から自重を自動加算しません。既存の桁受け重量・偏心・慣性力は既存集約値に1回だけ含まれ、柱頭N/Mの帰属は梁天端のままです。`load_anchors.cap_top`と`footing_centroid`はその節点、`column_line_load`は元の梁天端→基礎天端と存在するH2/H3/H4部材IDの順序、`pedestal`は梁天端の集約先と`automatic_self_weight=false`を記録します。数値荷重は複製せず、既存の作用高さ・腕・荷重値・係数を保持します。0610はこの対応をFrameWeb入力へ変換します。変位・部材断面力の解析は外部FEMPythonで行います。

元Excelの旧4点は`frame.legacy_nodes`に元id/x/y/source_rowと合流先`active_node_id`を残し、`cells`・`transfers`も監査用として保持します。元行は0610が81～84、0620が79～82で、新規境界には架空の元行を付けません。PDFの図・実節点表・接続表は拡張frameから生成します。材料・ばねと以降の荷重計算を保持し、モデル表が続く場合は後続を含め実出力順に頁番号を振ります。

1ページ目では黒い実骨組みの背面に、入力寸法に追従するパラペット・柱・梁／ハンチ・フーチングを薄い破線で描きます。線路方向はB、直角方向はW、高さはH1～H6を使用し、偏心・テーパーを保持します。外形と実骨組みには同じ縦横比の縮尺を使い、高さ0の部位に架空の厚みを付けません。フーチング重心高は物理外形の肩位置とは別です。
