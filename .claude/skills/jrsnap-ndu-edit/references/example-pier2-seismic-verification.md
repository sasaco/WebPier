# 朝里川温泉P1・線路方向の見本照合で確認した事項

確認日: 2026-10-17。以下は特定モデルでの `observed` な対応であり、全NDUの仕様ではない。

- 入力: [線路方向_朝里川温泉P1.ndu](../../../../.claude/docs/Example橋脚2/10_線路(耐震)/線路方向_朝里川温泉P1.ndu)。先頭は `Virsion=5.1.10.S.4`。CP932、CRLF、5573 bytes、SHA-256 `7511404fa1da9d67c5f89dd03b084831da322cfcf6764648a288673eb053c35e`。
- 見本: [10_線路(耐震).pdf](../../../../.claude/docs/Example橋脚2/10_線路(耐震).pdf)。全26ページ。1～7頁はモデル・断面・基礎ばね、8～12頁は荷重・組合せ、13頁以降は応答・照査結果。
- 同じフォルダーの `snap/*.ndt`（START 51）と照合し、節点・要素・支持・配筋・全荷重の対応を確認した。
- [入力照合結果](../../../../output/jrsnap-p1/線路方向_朝里川温泉P1_入力照合.json) に照合項目とPDFページ、未確認事項を記録した。既存の掲載入力が一致したためNDUを書き換えていない。応答解析の再実行はしていない。

## モデルと断面

- NDUの座標原点は節点5、yは下向き。基礎底面からの高さは `2.7 - JointXY<n>の第2フィールド` で比較すると、PDFの節点1～7の高さ10.300、8.300、7.600、2.710、2.700、1.350、0.000 mに一致する。原点や符号の違いを形状不一致とみなさない。
- 節点1のx=-2.980232E-07 mは、NDTの表示精度では0.000 m。PDFの直線モデルと矛盾せず、今回ゼロへ修正していない。
- 要素4だけが非線形番号1・断面番号1、長さ0.010 m。他の5要素は剛域。全長に0.010 mを追加しない。
- 矩形の `SectInfo1`（第2フィールド=1）は、第5=幅4500 mm、第6=高さ2700 mm、第10=せん断スパン7600 mmだった。形状コード15のT形断面とは寸法フィールドの意味が異なる。
- `SectRein1-1`～`1-11` の上面距離・径・本数はPDF6頁の全11行と一致。外側の各29-D32と中間の各2-D19を、全段数や両面合計本数と混同しない。

## 直接基礎の支持件数と別枠データ

- このモデルは `SuppotNum=3`、`SuppotRow=2`、`FootRow=1`。並進ばね2行と直接基礎回転ばね1行を合わせた3支点データで、NDTにも3行がある。杭周面支持専用の `SuppotNum=SuppotRow` という部分仕様を直接基礎へ流用しない。
- 解析用 `FootInfo1` は節点7、B=7 m、L=9 m、kv=405976 kN/m³、Df=3.78 m、φ=42.2度、KR2=2。PDF7頁のDf=3.8は表示の丸めで、23頁に3.78の記載がある。丸めた表示値へ入力を変更しない。
- Df・γ2の算出根拠は `.claude/docs/Example橋脚2/08_線路.pdf` 28頁にある。Df=表層厚3.780 m、平水位γ2=(1.080×18.0+2.700×9.0)/3.780=11.6 kN/m³。耐震PDF7/23頁とFootInfo第10フィールドに一致する。0500の表層条件と水位から導出できるため、既存コードにγ2キーがないだけで手入力必須と判断しない。水中重量・層厚は案件ごとに異なる。[WebPierとの比較・式・旧Excel値の区別](../../../docs/research/webpier-longitudinal-ndu-soil-derivation.md)を参照。
- `CHOKU_KISO1` は別枠の照査用データ。継続行に6、9、54、3.08等があり、解析用 `FootInfo1` と同一の入力だと決めつけない。見本にはこのデータの入力表がなく、今回の照合では意味・同値性の全確認はできていない。解析入力が一致しても基礎照査設定全体の再現を保証しない。
- `SoilRenkeiFile1` に他案件名の旧絶対パス、`NDTPath` に旧出力先、`Tisou` に18層のデータが残っていた。PDFに根拠がないため保持し、再連携・再出力を行わず未確認として報告した。
- PDFに載らない剛域A/I/E、`SectSafe1` 第3フィールド=1.05等も、独自の値で埋め直さない。

## 旧版を両版で保存したときの実測

`jrsnap-input-open-save/scripts/save-ndu.ps1` の検査モードで、インストール済みV52/V53の読込・保存処理を一時コピーに実行。両版とも再保存がバイト一致した。画面操作の検証ではない。

両版で保存された本文は同一で、ヘッダーはそれぞれ `5.2.3.S.4` / `5.3.1.S.6`。原本との差は、ヘッダー以外では次の7項目だった。

1. `DataInfo` 末尾に `,0,0,0`。
2. `SectInfo1` 末尾に `,0,0`。
3. `TanbuShiji1=0,0` 行追加。
4. `SectSafe1` 末尾に `,1.3`。
5. `FootInfo1` 末尾に `,20,-3.402823E+38`。
6. `CHOKU_KISO1` の先頭行末尾に `,20`。
7. `NDTPath` 行削除。

これは本モデルに対する保存処理の実測。マニュアルの新版既定値を旧モデルに一律適用しない。行追加による位置ずれを含む `BodyChangedLines=137` は、137個の入力値が変わったという意味ではない。原本へ新版保存を反映する場合は実際のキー単位の差分を確認する。

## 見本を使った作成依頼で既存ファイルがある場合

まず既存内容を照合する。既に掲載入力が一致するなら、作成を装うための再書込みやヘッダー変更はしない。既存を採用したこと、変更件数0、読込検証の版と方式、未確認項目、再解析の有無を区別して報告する。

## WebPierの新規生成で追加確認した5.2の形式

2026-10-17、インストール済みJRSNAP 5.2-L03（File/ProductVersion 5.2.3.0、AssemblyVersion 5.2.3.1）の読込・保存処理で一時モデルを確認した。詳細なキー・フィールド・単位・出典は [WebPierのフィールド対応表](../../../docs/research/webpier-longitudinal-ndu-field-map.md) に記録している。以下は確認した出力範囲であり、任意のNDU形式に一般化しない。

- readerは行の位置と順番に依存する。キーが同じでも `Member_BunpuBane` や `ShabuzaiMeInfo` を別ブロックへ移すと読込に失敗する。名前を辞書へ読み込めただけでは実アプリ互換を保証できない。
- `TishouNum=0` にしても `Tisou=` の空行は必要だった。行ごと削除すると後続読込で空文字からByteへの変換に失敗した。不要な旧地層の値を除くことと、構文上必要な空レコードを除くことを区別する。
- 1要素1部材の6部材構成、`ChokuKisoNum=0`、照査リンク無効、`SRenkeiNum=0`、`TishouNum=0` のモデルでも、解析用 `FootInfo` を保持して読込・保存できた。旧照査・連携データを新規案件へ自動コピーする必要はない。
- `DataInfo` 第20フィールドの0.001は収束判定値FTMであり、変位増分そのものではない。変位目標値と増分数は別項目。`TanbuShiji=0,0` は断面照査側の部材端条件であり、骨組の基礎支点条件ではない。
- `SectJikuNum` の上下面引張主筋段数は、上面距離順の全配筋から先頭／末尾N段を選ぶ。選択方向の入力行数だけを転記すると、側面筋が外側や段間に入る配置で異なる鉄筋を選ぶ。WebPier生成では意図する線路主筋と先頭／末尾N段の芯位置・径・本数・材質を照合し、一致しない配置はv1未対応として拒否する。主筋段数を自動で増やして辻褄を合わせない。公式5.2説明書90・530頁とnative DRTU/DRTL/DRTUV/DRTLV対応を根拠表に記録した。
- 実アプリの保存で数値の字面が正規化されるため、バイト差分に加えて意味と参照の照合が必要。WebPier候補では166レコード・623項目と8荷重の合力・基礎底面回りモーメントを独立期待値と照合し、2回目保存のバイト安定を確認した。件数はこのモデル固有。
- 一般の生成結果に実アプリ検証済みと書かない。生成時の付帯情報と、実際に読み込んだ同一候補を特定する受入記録を分ける。読込・再保存はGUI画面の確認、NDT出力、解析実行、耐震安全性の確認を意味しない。

WebPierで採用したVcd=2.0・Vsd=1.3・Vdd=1.8・Dmax=25 mmは、ユーザーが入力欄の初期値として明示指定した値である。JRSNAP共通の既定値に一般化せず、入力値として保持する。
