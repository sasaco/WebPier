# 現行の不整合と新プログラム化で決める事項

以下はソース・数式の確認から分かる挙動である。原本の修正は行っていない。「提案」は新プログラムの実装方針候補であり、現行仕様や合意済みの設計判断ではない。

## 2. 数値に直接影響する点

### F07: 回転ばねが両方向とも直角方向

`0500/支持層!U113/U116` は線路方向Kr、`U124/U127` は直角方向Kr。定義名 `Kr長期/短期` は後者だけを参照する。`直接基礎計算.bas:57–58` が読み、`線路荷重.bas:127–134` と `直角荷重.bas:280–287` が両方向へ渡す。

矩形基礎では一般に2つの底面二次モーメントが異なり、この現行処理はその違いを受け渡せない。提案するデータ構造は `Kr[方向][長期/短期]`。旧仕様との比較が必要なら、同じ値を渡す互換動作は別途明記する。

### F08: 終点側の支承位置が荷重アームに反映されない

`0620/荷重計算!Y5:Y14` にC側支承位置を入れるが、C側D1のアームは `V53=V43`、`V54=V44` … とB側を参照する。C側D2、列車・衝撃のアームもこれを継承する。

保存例ではB側が-2.441/+2.349m、C側入力が-2.556/+2.143mであるにもかかわらず、C側荷重のモーメントはB側位置で求まる。B/C別々の支承位置と力を対応付ける仕様が必要。

### F09: 分担後の反力を使わないモーメント

`0620/荷重計算!V134=ROUND(M134*R134,2)` は分担後反力だが、`AD134=ROUND(Z134*M134,2)` は分担前反力を掛ける。同じ形が安全列車・使用列車・地震列車・安全衝撃・使用衝撃の5表にある。

分担率0の支承にもモーメントが残り、分担率の変更が合計モーメントへ反映されない。候補修正式は `ROUND(支承位置*分担後反力,2)` だが、列車ケースや符号の扱いも併せて定義する。

### F10: 鉛直力合計に位置・モーメントが混ざる

同じ5表の集計は `V154=SUM(V134:AM153)`。V列の力だけでなく、Z列の位置とAD列のモーメントも含める。V181/V208/V238/V265も同形。

保存例の安全列車はV列だけの合計1140.92kNに対し、V154は1035.776となる。力・位置・モーメントを同じ合計範囲に含める根拠はない。集計対象は物理量ごとに分ける。

### F11: 単線ケース選択が成立しない

`直角荷重.bas:205–247` のコメントは最大偏心ケースの選択を意図しているが、実装には次が重なる。

1. 今回のD1/D2/列車荷重を転記する前に比較する。
2. 有効候補の判定に使う分担率合計がC側だけとなる。
3. 比較は符号付き `MD1+MD2+ML` で、絶対値でも軸力で除した偏心でもない。
4. F09によりMLは候補の分担率から独立している。
5. 初期値0以上の候補がなければ `keyi=0` となり、分担率の直上行（D2）を転記する。

保存値例はMD1=-295.13、MD2=0、ML=-104.96で合計-400.09。この状態の数式で分担率だけを変えても、比較値は変わらない。

提案: 先に全入力を固定し、各列車ケースのB/C別支承反力からN・M・偏心を計算する。採用基準を「符号付きM」「絶対M」「絶対偏心」「照査上の最不利」から明示的に選び、候補なしもエラーとして扱う。何を最大化すべきかは現行コードのコメントだけでは確定しない。

### F12: 遠心入力が荷重集約へ接続されない

0620のP275:P277 / X275:X277には0600で求めた遠心荷重が入る。一方G287は固定文「直線区間のため 遠心荷重は考慮しない。」で、車両横や風のような天端H/M集約式・基本荷重ケースがない。

現在の `input.xls` は両側R=350m、V=95km/hで、曲線入力を持つ。また遠心方向記号X5/X8を転記する処理もない。曲線対応・正負方向を新たに定義する必要がある。

## 4. 保存値を期待結果にできない理由

ブック間にも、同一ブック内にも、入力と結果の世代の違いがある。

| 比較箇所 | 確認した不一致 |
|---|---|
| inputと0500 | inputの支持層は砂質土、0500保存入力は安山岩。ばねの土質係数が異なる |
| inputと0600 | inputの支間は27/25.2m・軸重170、0600の列車表の保存入力は72.6/72.6m・軸重150 |
| 0600直角荷重の入力とVBA結果 | 入力は横移動荷重30・支間72.6m、保存された計算式文字列は荷重34・支間27/25.2mを使っている |
| 0500と0610/0620 | 0500の保存Kv長期1713058に対し、0610/0620の保存入力には3657924が残る |

0600直角荷重の根拠セルはS73、E4/H4/K4、E5/H5/K5、K87/K94。保存FB/FCは56.3518524/66.3134918であり、現在の同ブック入力を実行した正解値とは扱えない。

回帰データを作るなら、入力・テンプレート・計算エンジン・丸め・採用ケースを揃えた実行を別途記録する。今回の静的解析は、その前提を明らかにするためのもの。

## 5. 未接続機能と外部依存

この開始経路には、杭基礎ばね、骨組解析の実行、柱・フーチングの耐力照査、配筋決定、断面寸法の反復探索はない。

未接続ブックには独立した処理がある。

- `0612_線路方向柱.xls` の `Send.bas` は、断面データをJSONにして `http://www.structuralengine.com/RCnonlinear/api/values/` へ同期POSTするコードを持つ。
- `三次元骨組解析.xls` の `Send.bas` は、`http://www.structuralengine.com/FrameWeb/App_Script/Web_Api.py` へ `inp_grid=` とJSONを送るコードを持つ。
- `0700_基礎フーチング.xls` には地盤反力・断面力・断面照査用の関数、`0710_杭基礎フーチング.xls` には集計やテキスト読込みの処理がある。

これはVBA内の文字列・呼出しの確認であり、現在そのURLが稼働すること、計算内容が同一であることは確認していない。今回通信は行っていない。これらを新しい一括設計へ組み込む場合は別の入出力契約を調査する。

現行の実行環境依存としてExcel VBA・ShapesとWindowsの `Scripting.FileSystemObject` がある。`comon` は `Dim FSO As Scripting.FileSystemObject` と早期バインディングの型宣言を使い、参照設定にも依存する。新実装でExcelを計算エンジンにするか帳票だけに使うかは未決定。

## 6. 新プログラムの切分け案

現物から抽出できる機能の境界は次のとおり。言語・フレームワークの決定や実装は今回の対象外。

1. **入力モデル**: 幾何、地盤層、上部構造、B/C別支承、列車・荷重条件。値・単位・座標基準・欠測を明示する。
2. **基礎ばね**: 土質別係数、長期/短期、方向別Krを返す。
3. **橋脚自重**: 各部の体積、重量、重心、上載土、浮力を返す。
4. **列車反力**: 軸生成、配置候補、釣合い、最不利配置、説明用の計算内訳を返す。
5. **荷重生成**: 列車・衝撃・遠心・車両横・風・レール・制動・地震をケースID付きで生成する。
6. **方向別モデル・荷重集約**: 支承位置と分担率を適用し、N/H/Mと分布荷重を構築する。
7. **解析・照査**: 現入口では未接続。解析器・部材照査・杭基礎・設計反復の範囲を別途定義する。
8. **帳票**: 確定済みの計算結果を表示する。図やExcel操作の失敗が計算そのものを変えない構成にする。

まず決める必要があるのは、既存コードの不具合まで比較用に再現する範囲と、修正した設計式を採用する範囲、そして「自動設計」が荷重生成・照査・最適化のどこまでを含むかである。

## 7. 後続実装で使う検証ケース案

以下は**今後の受入試験案**で、今回実行した試験ではない。

| ケース | 確認すること |
|---|---|
| 正方形／矩形基礎 | Krの方向一致／相違と渡す先 |
| 砂質土・粘性土・その他、支持層なし・重複 | 土質係数、層選択、エラー扱い |
| 1両／多両、2軸／4軸、張出し、桁境界上の軸 | 反力釣合い、二重載荷防止、RB+RCの共通最大配置 |
| 最大反力が同値の候補 | 候補列挙順と採用規則 |
| B/Cが非対称の支承位置 | 各側の正しいモーメントアーム |
| 分担率0/1、合計1、Bのみ/Cのみの列車 | 支承反力・モーメント・候補判定の連動 |
| 単線の正負モーメント、全候補負、候補なし | 採用基準とkeyi=0相当の防止 |
| 曲線／直線、遠心方向の反転 | 水平力・作用高・組合せへの反映 |
| 水位が基礎下・基礎途中・柱途中 | 浸水体積、浮力の負符号、重心基準 |
| 手動計算状態、出力失敗、途中エラー | 旧値を成功として返さず、原本・前回結果を保つ |
| Excelと新エンジンの丸め境界 | 中間ROUND、Single受渡し、許容差 |

荷重・位置・モーメントの合計は、同じ式の再実装だけでなく、独立した釣合い・単位・分担率の検査でも確認する。
