# 調査根拠と確認範囲

## 1. 根拠ファイル

| ファイル | 内容 |
|---|---|
| [workbook-inventory.json](evidence/workbook-inventory.json) | 解析時点の10ブックの相対パス、SHA-256、サイズ、VBAモジュール・シート一覧 |
| [workbook-structure.json](evidence/workbook-structure.json) | 主経路5ブックのシート名・CodeName・マクロ割当のある図形 |
| [defined-names.json](evidence/defined-names.json) | 主経路5ブックの同一ブック内業務用定義名363件 |
| [cell-formulas.json](evidence/cell-formulas.json) | 主経路5ブックの数式3,095件。ブック→シート→セルアドレスの辞書 |
| [formula-ranges.json](evidence/formula-ranges.json) | Excelが数式として分類するセル範囲。表示用の「=」などの定数と分離する根拠 |
| [constant-cells.json](evidence/constant-cells.json) | 同じシートの非数式セル。係数、荷重組合せ、固定文章、保存されたVBA結果を含む |
| [source-recheck.json](evidence/source-recheck.json) | 作業中にバイナリ変更を検出したブックの変更前後ハッシュと内容差分確認 |
| `evidence/vba/input/` | 開始経路の標準モジュール6本 |
| `evidence/vba/0600_上部工反力/` | 呼び出される標準モジュール3本 |

`constant-cells.json` の数値は**入力だけではない**。VBAが過去に書いた結果セルも非数式セルなので含まれる。今回の実行結果や、新プログラムで変更可能な入力一覧としては扱わない。`ご利用方法` の認証欄は数式・値資料から除外した。

定義名資料からは印刷範囲・旧グラフ用の外部名・参照切れ名・認証名を除いた。これらの残存を「存在しない」とする意図ではない。本文で重要なものを別途説明している。

VBAはOLEから取り出したテキストをUTF-8・LFへ正規化したもの。コードのロジックは編集していない。本文のVBA行番号はこの抽出物に対応する。ExcelのVBE表示では属性行の扱いが異なり、同じ行番号にならないことがある。

## 2. 調査手順

1. Gitの作業状態を確認。開始時から `pre/input.xls`、`0500_直接基礎.xls`、`./pre/input.json` に既存の差分があった。
2. `oletools.olevba.VBA_Parser` でサンプル内の10冊からVBAを静的に抽出。
3. `xlrd` で同じファイルのシート・定義名・保存セル値を取得し、SHA-256を記録。
4. 独立したExcelインスタンスを作り、`AutomationSecurity=3`、`EnableEvents=False`、`UpdateLinks=0`、`ReadOnly=True` で主経路5冊を読取り。
5. `UsedRange.Formula`、`Value2`、`Names.RefersTo`、`Worksheet.CodeName`、`Shapes.OnAction`、`LinkSources(1)` を取得。数式セルは `SpecialCells(xlCellTypeFormulas)` でも確認し、表示用の「=」138セルを数式から除外して定数へ分類。
6. 読取り用Excelは計算モードを手動にし、終了時は必ず `Close(False)` と `Quit`。開始マクロは呼ばない。
7. VBAの呼出し順・代入とセル数式・定義名を突き合わせ、入力画面にあっても未使用の項目、未接続の設計ブック、保存値の不整合を分類。
8. 主経路と方向別計算の調査を別担当で行い、最終文書を相互確認。

最初の読取り用ブックを開く際の計算状態まで完全に再現する試験ではない。保存値の根拠にはExcelによる読取り値だけでなく、`xlrd` で読んだ元のキャッシュを用いた。数式を読めたことと、マクロ一括計算を成功させたことは別である。

## 3. 調査中に検出した別の更新

調査途中に0600・0610・0620・0700のバイナリハッシュ変更、および `.claude/docs/Example橋脚/output` のPDF追加を検出した。今回の調査処理はそれらを作成・保存していない。

変更後ファイルを解析用フォルダーへ複製し、VBA・保存セル値を変更前の抽出物と比較した。さらに主経路の0600・0610・0620は数式・定義名を再読取りして比較した。比較結果は `source-recheck.json` に記載する。出力PDFの作成や別変更の検証を今回の成果として扱わない。

このwikiは `workbook-inventory.json` の版を基準にしている。原本が今後変わったら、ハッシュだけでなく、VBA・定義名・セル数式・定数表の差分を確認して更新する。

## 4. 確認したこと

- 開始ボタンから呼び出す4処理と、0600内の3つのマクロの対応。
- 直接基礎以外の分岐、保存・閉じる処理、開いているブックの探索条件。
- 入力の転記列・行、10支承の並べ替え、4行の候補と2行転記の相違。
- 移動荷重の候補列挙、RB+RC最大化、桁境界軸の割当て。
- 地盤ばねの数式・丸め・土質分岐と方向別Krの受渡し。
- 0610/0620の荷重表、荷重組合せ、単線選択、支承位置・分担率・合計範囲の不整合。
- 到達先VBAとセル数式の根拠をwiki内へ保存し、リンク・JSON・コード一致を確認。
- 単線候補の相対0行が入力範囲の直上を指すことを読取り確認。`列車分担率B.Cells(0,1).Address` は `O22`（D2行）。

## 5. 今回は検証していないこと

- 原本または複製での開始ボタンの実行成功、対話画面・作図・保存を含む一連の動作。
- 図形・帳票の見た目、印刷範囲やPDFのレイアウトの正しさ。
- 旧設計標準や現行基準への適合、各荷重係数・材質・モデルの採用妥当性。
- 未接続ブックの全機能、外部APIの稼働・応答・計算内容。
- 単線選択や回転ばねなどを修正した後の数値結果。

既存の開始経路に含まれる数式は収録したが、全3,095式を個別に正当性評価したわけではない。本文は制御フロー、入力契約、主要計算式と確認できた不整合を対象とする。

## 6. 再調査の方法

原本のハッシュを取得し、`workbook-inventory.json` と比較する。マクロを見るときはExcelから実行せず、OLE/VBA抽出を使う。数式が必要な場合はマクロ・イベント・外部リンク更新を無効にした独立Excelで読み取り専用にし、保存せず閉じる。

今回の補助スクリプトと全抽出中間データはリポジトリの無視対象 `tmp/pier-macro-analysis/` にある。そこは成果物の依存先ではない。調査結果を読むために必要な根拠は本wikiの `evidence/` に含めた。

後続で動的検証する場合は、入力・テンプレートの複製一式を用意し、F01等の実行障害をどう扱うか明示する。修正前の再現結果と修正後の結果を混ぜず、採用された載荷位置、方向別ばね、各荷重ケースのN/H/M、保存先まで記録する。
