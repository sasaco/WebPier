# .claude\docs\Example橋脚2: 線路直角方向 PDF と FrameWeb JSON の対応調査

調査日: 2026-10-16。WebPier直角方向エクスポートの計画に用いる読取調査。既存PDF・JSON・アプリ・旧計画は変更していない。

対象は `.claude/docs/Example橋脚2/09_直角.pdf` と `.claude/docs/Example橋脚2/09_直角/frameWebForJS.json`。PDF全29ページをテキスト抽出し、入力に対応するp1〜15および結果のp16〜17を描画して目視確認した。物理ページnと印刷ページ`9 - n`が対応する。作業画像・抽出文は `tmp/webpier-transverse-frameweb-plan/example/` に保存。

このメモの「確認」は当該PDFとJSONの直接照合に基づく。FEMPythonの一般仕様や設計基準の正当性を認証するものではない。例題の入力・図・結果に不一致が存在するため、例題JSONの機械的な複製はWebPierの実装方針にしない。

### 4.1 D1/D2と対称荷重

p3の固定死荷重は次のように構成される。

- 柱q=2.70×4.50×24.5=297.68 kN/m。
- フーチングW3=24.5×7.00×9.00×2.70=4167.45 kN。
- 上部反力: 起点G1〜G4が1530,1340,1340,1530、アーム-3.8,-1.5,+1.5,+3.8m。終点G1/G2が930,930、アーム±2.95m。各対のモーメントが打ち消される。
- 梁1190.70、ハンチ104.19を足した集中鉛直力合計8894.89 kN。
- 天端N=8894.89−297.68×2.00=8299.53 kN。柱モデルの梁高2.00m分と上部重量の重複を控除する。
- M=0。線路方向例題の偏心モーメントを流用してはならない。

`load.1.load_member[0]` は `m1="1",m2="3",direction="x",mark=2,L1="0",L2=0,P1=P2=297.68`。上から下へ向く部材局所xの正方向と下向き自重が整合する。2行目はP1/P2=nullの空行。

D2はp3の土重量2268.00−437.40=1830.60をnode5、上部反力160+100+100+160+130+130=780.00をnode1へ載せる。水平アームが対称なのでM=0。D2には `load_member` 自体がなく、土荷重を分布荷重として柱に載せていない。

雪荷重も左右の反力対が対称で全ケースM=0。浮力はp4の-10×7×9×水深（3.78/2.70/0.00）で、下向き正の表値を反転しnode5のtyに正値を入力する。これは静的浮力であり、動水圧荷重ではない。

### 4.2 列車・衝撃の上り下り

p5列車単線上りは支点配分係数、支点位置を用いて合成している。起点反力272.47に係数(-0.020,0.176,0.373,0.471)、終点反力294.92に(0.143,0.857)を掛け、アーム(-3.8,-1.5,+1.5,+3.8,-2.95,+2.95)でMを合成する。上り合計N=567.39、M=+1210.08。下りは配分の左右を入れ替えNを保持し、Mだけ-1210.08となる。

p6衝撃も上り/下りの鉛直力は同じ227.78、Mのみ±483.45。複線は左右対称でN=1134.77（列車）、428.28（衝撃）、M=0。

**上り/下りは基本ケース全体の単純な正負反転ではない。** `-load9`を下り代替とすると鉛直力が上向きになってしまう。別の正ID 9/10、12/13を選ぶ必要がある。

### 4.3 車両横荷重

p7はH=52.71+58.98=111.69 kN、M=52.71×3.85+58.98×3.85=430.01 kN·m。p11図ではH右向き・M時計回り。しかしJSONは `tx=-111.69,rz=-430.01`。風の右向きH→tx正という対応と矛盾する。

JSONの符号のままなら、基部y=0に対する外力モーメントは `-430.01−10.3×(-111.69)=+720.397`。cached `result.15.reac.6.mz=720.3970000009285` と一致する。図のH右向きを採用した場合は `-430.01−10.3×111.69=-1580.417` となる。Defineで全体を±してもHとMの相対符号の差は解消しない。

### 4.4 風荷重と部分載荷

p7/p8より、列車ありH=197+108.88=305.88、M=1001.33。列車なしH=394+217.75=611.75、M=2002.64。Mは桁水平力×鉛直アームと、シェルターの鉛直反力×水平アームの合成である。風による鉛直反力の総和はゼロのため、JSONはtyを別途載せずMとして集約している。

### 4.5 対象外の荷重

本資料のp1見出しは「地震時以外」。17基本ケースには地震力、動水圧、遠心荷重、ロングレール縦荷重、制動荷重の独立ケースはない。PDF p3〜8の作用計算項目も固定死・付加死・浮力・雪・列車・衝撃・車両横・風である。WebPierにこれら以外の荷重が必要かはWebPier自身の条件で決めるべきであり、例題にないことだけを理由に削除・追加しない。

p13のDefine表はJSON全行と一致する。行番号は基本ケースIDと途中から異なる。

この対称例では独立組合せを作っても最大|M|は同方向の組となるため、PDFの包絡最大値一致だけでは連動仕様を証明できない。非対称な小モデルで仕様を区別する検証が必要。

車両横と風の正負Defineは両者のC1/C2を常に同期すべきか独立かも明示されていない。PDF結果は車両横と風の曲げが加算される包絡を使用している。列車選択の連動と、独立した風方向の選択を同一視しない。

## 7. resultキャッシュとPDF結果の照合

`result` は生成入力値ではなく保存済み計算結果。キーは基本荷重ID1〜17のうち5を除く16個。各値は `disg`, `reac`, `fsec`, `shell_fsec`, `size` を含む。`size=6`、shell_fsecは空。風ケース16/17のdisgには入力6節点以外に分布荷重端の生成節点`3l1`がある。

16有効ケースすべてについて、JSON入力から単純合力（ΣFx,ΣFy,原点まわりΣMz）を独立計算し、cached `result.ID.reac.6` のtx/ty/mzと最大絶対差2.563e-9で一致することを確認した。このreacは外力と同じ符号で記録されており、自由物体図の支点反力をそのまま同符号とみなさない。

代表値:

- D1: `ty=-(8299.53+4167.45+297.68×7.60)=-14729.348`。
- D2: `ty=-(780+1830.60)=-2610.60`。
- Case15: `tx=-111.69,mz=+720.397`。図と異なる水平符号を実際に反映。
- W1: `tx=332.286,mz=-4337.79224`。
- W2: `tx=664.562,mz=-8674.82148`。表の2002.64でなく入力2002.00を反映。

p16〜17の柱基部は部材3のJ端（部材内L=4.900m）。cached `result.*.fsec.3.P1` に対応する。

| PDF結果 | cached結果を用いた照合 |
|---|---|
| 変動作用、M=1572.67 (p17) | 1210.08+0.75×483.45=1572.6675 |
| 安全性破壊、M=8256.60 (p16/17) | W2柱基部M=6880.50408×1.2=8256.604896で一致 |
| 安全性破壊、V=797.47 (p17) | 664.562×1.2=797.4744で一致 |
| 復旧性、M=3955.78 (p16/17) | W1柱基部3440.62004+1.23×Case15柱基部|−418.834|=3955.78586。小数2桁では3955.79となり約0.01差 |
| 復旧性、V=469.67 (p17) | 332.286+1.23×111.69=469.6647。小数2桁では469.66となり約0.01差 |

PDF安全性破壊結果は、W2の2002.64という表値より、JSONの2002.00を用いた結果に一致している。表値に修正すれば柱基部M×1.2は8257.372896になる。

Case15を図どおりtx=+111.69,rz=-430.01とすれば、柱基部の同方向合成モーメント絶対値は `430.01+111.69×7.6=1278.854`。W1との復旧性包絡は約5013.61となり、PDFの3955.78と大きく変わる。したがって既存結果が再現できることだけでは、荷重図の意図に合うことを証明できない。

WebPier入力作成時にはこのresultをコピーしない。解析するならWebPier入力から再計算し、原入力由来の値と新結果を混在させない。

## 8. 丸め・不一致・確認境界

確定した不一致・注意点:

1. **Case15 H符号**: p11右向き図に対し `load.15.load_node[0].tx=-111.69`。Mは双方時計回り対応。±ケースの反転でも相対符号不一致が残る。
2. **Case17 M値**: p8/p12 M=2002.64に対し `load.17.load_node[0].rz=-2002`。cached結果とp16/17安全性結果は2002.00側。
3. **列車M矢印**: p11列車のM矢印は反時計回り、同ページ衝撃は時計回り。表値とJSONは列車も衝撃も `rz=-M`。矢印だけを根拠に別符号規則を作らない。
4. **単位誤記**: p9 D1のN/M/PがkN/m表記、p10浮力PもkN/m表記。p11車両横M・p12風MはkN表記。p7/p8のく体風qはkN表記。計算寸法とp3〜8の表・p12分布荷重表記から、集中力kN、モーメントkN·m、分布kN/mと判断する。
5. **複線ラベル**: p13はL3/I3、p14の同じDefine列番号10/12はL2/I2。数値参照は一致。
6. **表示丸め**: p5単線の表示成分合計は567.38だが合計表示567.39。複線1134.77は単線表示567.39の2倍と0.01差。q=297.675→297.68、Iz=20.503125→20.50313。表示係数・部分値から内部精度を復元しない。
7. **結果の小差**: 復旧性のM/VはJSONキャッシュの組合せと小数2桁で0.01差があり、PDFとJSONの完全同一再現は成立しない。
8. **支持条件の不一致なし**: 本直角例題では全17ケースでp13とJSONが一致する。別方向例題で見つかった支持条件差を持ち込まない。

PDFだけでは未確定:

- 剛域A=Iz=1000、Xp=1e-5などソフト用既定値の必須性。
- `m2=-3`の一般的な範囲展開と局所y正方向のソース上の仕様。
- Define9/11の上り下り連動と、Define13/14/15の風・車横の方向選択規則。
- 荷重図のCase15符号と結果のどちらを設計者が意図したか。
- 風の非載荷1.08mの設計根拠（数値は高水位からの高さと一致）。

## 9. WebPier実装計画に必要な検証

1. WebPierの直角方向PDFと生成元の型付き結果から、同じ列項目の対応表を作る。例題にないD2分布、非対称鉛直力、風・遠心・動水・地震等がWebPierに存在するかを独立に確認する。
2. 柱曲げ方向のIz、回転Kr、節点高さ、分布載荷区間をWebPier自身の値で確定する。
3. 正負の分類を分ける。列車上り/下りはN保持・M変更、風の向き反転はH/M/q全体変更。水平成分だけ、モーメントだけの反転を無根拠に行わない。
4. 基本ケース、Define行、combine列は別ID空間として扱う。15基本以上へ拡張する場合にも「同番号だから同荷重」という推測を避ける。
5. 部分分布荷重は合力・作用高さ・柱基部Mを独立に検算し、分割節点によって二重計上や各部材ごとのL2控除が生じないことを確認する。
6. 例題不一致は期待差分として台帳化し、WebPierのPDF準拠値と例題JSON再現値を区別する。入力だけでなくcached結果も誤差・不一致を引き継ぐことを検証に反映する。
7. WebPier出力には例題resultキャッシュを混入させない。再生成対象の入力だけを作り、解析検証が必要なら新しい結果として別途得る。
