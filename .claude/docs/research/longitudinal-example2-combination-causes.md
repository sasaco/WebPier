# 0610 Example2 組合せ差の原因と移行案

2026-10-16。読取り調査のみ。製品コード・入力・出力・既存計画・既存 oracle は変更していない。以下のコード位置は調査時点の dirty tree に対するもの。前回PDF比較後の更新を読み直した。

## 確定した原因

根本原因は入力値の違いではなく、0610の組合せが `.claude/docs/Example橋脚/0610_線路方向荷重.xls` を固定採用し、Example2の体系へ置き換わっていないこと。

| 差 | 直接の実装根拠（`./` 基準） |
|---|---|
| 旧21基本・20組合せを保持 | `pier_design/longitudinal_combinations.py:10-55` の固定表を `longitudinal_calculator.py:344-361` が無条件採用。出典も同144、150に旧xlsと旧表保持を明記 |
| 使用性永久＋変動が単線 | `longitudinal_calculator.py:102-108` が使用性の列車・衝撃を単線だけ転記。`_load_groups` の328-329、`_combinations` の347-348が用途別2基本に固定。固定表 `longitudinal_combinations.py:42-43` がその単線基本を使う |
| S2/S10鉛直基本と組合せがない | 入力は `reaction_inputs.py:19-22,345-388`、独立集計は `reaction_weights.py:71-103`、0600結果は `reaction_calculator.py:374,411` で3確率存在。0600水平力は同184-191に雪を使用。0610で同カルキュレータ198-205がS30だけ抽出し、225-235が旧20列へ0を追加、S30/LR専用4列だけ追加するためS2/S10が途切れる |
| 使用性1.0LRのばねが2 | `longitudinal_combinations.py:21` の固定分類。Example2基本14は1 |
| 基礎LR欠落、制動最大でも衝撃有 | 同48-51：制動単独基本12/13を選択、LR+B基本14-16は0。基礎2/4にも衝撃基本8=1。LR最大列そのものがない |
| 高水位／平水位／低水位の追加、死荷重0.9/0.8の追加 | 同39-47、50-54の固定表。入力の水位を計算して判定した結果ではなく表体系そのものの違い |
| 地震基本と基礎地震列 | 同28-31、55の旧表に由来。Example2指定p9-11の体系にはない |
| S30の基礎復旧性列が余分、基礎安全性のLWL欠落 | `longitudinal_calculator.py:225-235` が躯体と基礎に同じ安全性／復旧性の2列を追加し、水位係数をすべて0にしている |

| PDFの表が柔軟でない | `longitudinal_report_reference.py:51-57,81-86,95-100,112-143,165-168` が21/24基本、躯体12/基礎8、S30追加4列と固定 |

元の雪入力計画 `.agents/docs/plans/superstructure-snow-reactions.md` は0610/0620連携を対象外としていた。その後0600水平力と0610 S30だけが拡張されており、現README:278と `tests/test_reaction_snow_integration.py:83-110` は「旧表保持」を明示的にテストする。したがって既存テストが通ってもExample2一致は保証されない。

### Defineと抽出（p9、p11）

- Define ID1-12はC1に同じ基本ID。ID13-20はC1=+ID、C2=-ID、C3空欄。水平作用の符号選択として保持する。
- 負方向の定義では鉛直D/S/L/Iまで反転しない。組合せ全体に-1を掛ける実装は不可。列車無しLR基本18/20も正負対象。
- 抽出: 安全性破壊=[1,2,3,4]、永久＋変動=[5]、永久=[6]、変動=[7]、復旧性損傷=[8,9]、安全性安定=[10,11,12,13]、長期支持=[14]、短期支持=[15,16]。
- p11の項目名欄に印字された「0.375」は意味未確定。支承間隔等の計算因子として採用しない。抽出組合せIDの事実だけを実装対象にする。

## 実装計画への提案

1. 旧xls固定定数は保存し、Example2用のケース定義を新 `pier_design/longitudinal_example2_cases.py` 等へ分離する。入力値・PDFファイル名・雪値の有無で無言の体系切替をしない。通常0610をExample2体系へ移行する場合、出力の `case_model_version`/`case_profile` と結果 `schema_version` の変更を明示する。入力schemaは現行1を維持可能。
2. `longitudinal_calculator.py` で雪3確率をそれぞれDouble転記し、支点腕と各支点丸めを保持。L1/L2/I1/I2を用途別旧2基本から分離した無係数基準値として準備し、水平8基本は0600の意味付きケースIDに対応付ける。旧`horizontal[10]`等の位置依存は新体系に持ち込まない。
3. `basic_cases`/`combinations` を新アクティブモデル、`define_cases`/`extraction_cases` を明示配列として追加。原資料IDと意味付きkeyを併記。組合せの列順は基本case IDの明示配列で固定し、疎辞書から完全20×16へ展開。範囲外ID、重複、係数長、抽出参照を検証する。
4. 元 `cells`/`transfers`/旧組合せのExcel証拠は `legacy_source` 等の監査名前空間へ保持するか、明示legacy API/profileで再現する。新活性ケースへ架空xls行/列を付けない。activeとlegacyを同じ`source_row`/配列位置で混在させない。旧21/24配列を消費する箇所はrgで全追跡し、README・renderer・テスト・CLIを同時移行する。
5. `longitudinal_report_reference.py` の固定行列・S30追加頁ロジックを、新モデルから基本／Define／20×16係数／抽出を描く処理へ変更。骨組モデル境界計画で承認済みの実節点表・継続頁・通し頁番号を保持する。固定旧頁番号ではなく内容で照合し、全頁を画像確認する。
6. 地震・慣性力はExample2指定の非地震16組合せへ混ぜず、現在算定済みの情報は別グループ／付録に保持する案が互換性上安全。これらの削除・安全性の追加低減ケースの廃止を設計一般の正誤と断定せず、Example2プロファイルの範囲として明記する。
