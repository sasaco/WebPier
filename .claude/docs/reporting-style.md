# WebPier 計算書の体裁契約

2026-10-17 に見本から測定した **体裁の独立測定値** であり、見本の数値・計算式・ケース数を WebPier の計算仕様に採用する文書ではない。全6帳票のページ数は内容に応じて変わり、見本の頁数や白紙頁は拘束しない。

## 根拠と再測定

原本は `.claude/docs/Example橋脚/output` の4冊69頁。`tests/fixtures/reporting/appearance/reference-census.json` に全頁の寸法、回転、書体/サイズ、等号X、罫線中心/太さ、見出し、白紙判定を保存した。`reference-style.json` は意味役割を人が選び、その選択箇所を原本から直接抽出した契約である。`page-roles.json` は全69頁の構成台帳で、機械的な罫線本数による分類とは区別する。図の寸法線が多いだけの頁を表として扱わない。

原本のSHA-256は各fixtureに保存し、検査時に再確認する。測定器は `scripts/reporting_appearance.py`、抽出器は PyMuPDF 1.28.2。原本を変更・再保存せず、製品コードや新しいbuilderをimportしない。

```powershell
uv run --project "." --locked python -X utf8 "./scripts/reporting_appearance.py" ".claude/docs/Example橋脚/output" "./tests/fixtures/reporting/appearance/reference-census.json"
uv run --project "." --locked python -X utf8 "./scripts/reporting_appearance.py" ".claude/docs/Example橋脚/output" "./tests/fixtures/reporting/appearance/reference-style.json" --style
```

このコマンドは原本測定の再現用。新PDFから期待値を作り直す用途には使わない。

## ユーザー指定と許容値

- 本文・数値・罫線は黒、表背景は白。赤/青の数値、黄色の見出し背景は意図した変換であり、原本色との一致を要求しない。
- 書体faceは一致。PDF subset prefixだけ除去し、MS-MinchoとMS-PMincho、MS-GothicとMS-PGothicは区別する。
- 通常サイズ差は0.1pt以内、共通アンカー相対位置と同構成の表行高差は0.5pt以内。原本比較を自己golden一致で代替しない。
- 新しい内容量に応じた改ページのため原本の絶対Y・頁数は検査しない。見出し/本文等の役割に対する相対Xと、同じ式/表内の基線差を検査する。
- 文字縮小や横方向の伸縮で収めない。大きい式や表は意味のまとまりを保って分割する。

## 書体と階層

基本本文は **MS-Mincho 9.9pt**、見出しは **MS-Gothic 9.9pt**。添字は6.5pt。0500の地盤表は見出しも値もMS-Gothic 9.9ptだが、通常の反力表・組合せ表はMS-Mincho 9.9pt。一律に本文faceへ変換しない。

原本0500p1の地盤表「一軸圧縮強度」だけは MS-Gothic 8.9pt（x457.32、基線195.598pt）である。`foundation.table_header_compressive` の固定役割として記録する。同じセルの単位行9.9pt・上付き6.5ptや他の見出しサイズを変更する根拠ではなく、任意の文字縮小も認めない。

原本の補助役割にはMS-PMinchoの支持力記号、TimesNewRomanPS-ItalicMTの衝撃係数記号、MS-PGothic 9.9ptの外形図題、Calibri 8ptの外形寸法がある。骨組図の節点/寸法にはMS-Gothic 9.9ptまたは8ptがある。数式を比例faceへ無差別変換する根拠ではない。実装で使うfaceとローカルファイル/face index/hashは共通runtime側に記録する。

## 行送りと空き行

見本の基線差のヒストグラムでは14.3ptと28.6ptが支配的で、見出しの前後は28.6pt（空き1行）である。これを次の規則とする。

- 行送りは本文・式・数式行とも一律 **14.28pt**（`Leading`）。6.5ptの下付き添字が0.07ptはみ出すのは `overhang=0.12` で許し、行送りを広げない。`Leading` は厳格（`minimum=False`）で、14.28ptを超える行は `LayoutOverflowError` になる。
- 見出しの前後は必ず空き1行（基線差28.56pt）。見出しが続いても空き行を重ねず、42.84ptにしない。
- まとまり（記号式の組、「ここに、」の定義、「・長期」とその式など）の間は空き1行。
- 表・図の前後も空き1行。表の題と表の間は空けない。
- 頁頭に来た空き行は捨てる（`spacer()` = `Spacer(..., discard_at_page_top=True)`）。空き行は `blank(out)` で足し、二重にしない。

## 式の書き方

- 代入式の右辺は数値を右揃え、演算子を中央揃えにした列に置く（GridLayoutPdf `TermStop`）。数値と演算子の間は見本0500p1「5.1 × 0.5 × 68600」で9.2〜9.4pt、0600p16の導出列で5.8〜8.7pt。全帳票で1つの値 `TERM_GAP = 7.44pt` とし、0600の狭い導出列（第1等号276.72〜結果等号436.44）で「T = 1.0 × LR = 1.0 × 200.00」が結果と同じ行に収まるようにする。
- 連続する式は1つの `equation_group` に入れ、行をまたいで項の列をそろえる。列を共有するのは項の列の形（列数と各列の揃えの並び）が同じ式どうし（または両方とも列なし）だけで、形の違う短い式（「T / n = 200.00 / 2」）を長い式の列幅に引き伸ばさない。結果の等号・結果の右端・単位は前述の意味構成ごとの列に置く。
- 1行に入らない式は通常の折り返しに退避する（行内の項の間4.95pt）。`"("`…`")"` は1項にまとめ、括弧の中で折り返さない。
- 分数は横書き「a/b」とし、積み分数は使わない。積み分数は14.28ptの行送りを壊す。
- 「ここに、」の定義は記号を右揃えにし、全角コロンの列をそろえる（0500はx211.0付近）。「(= 値 単位)」も列にそろえる。
- 見出しの出典（【基礎標準 13.2.2.2】等）は見出しと同じ行で、見出しの右端+9.9pt以上となる 340.8 + k×14.52 の最小のxに置く。
- 入力票の記号（B1〜B9、H1〜H6、W3〜W9、df1、df2）は計算書で定義されていないので印刷しない。式は値の代入式にするか、計算書内で定義した記号を使う。風荷重のW1/W2は設計記号なので使ってよい。

14.52、14.28、14.88、12.84、23.04、28.56ptはいずれも0.12ptの整数倍である。微細gridの刻み0.12ptを実測が支持する。既定15.48ptの行へ小さな表行を丸め直すと行高が変わる。微細gridの全線を通常/検査PDFに描かず、同じ確定layoutへ粗い検査線だけ加える。

0710/0720には直接の見本がない。共通見出し/本文/等号構成を0600、骨組図と座標表を0610/0620、作用組合せを対応方向の表から適用する。新しい計算内容や表示因子の省略を許可するものではない。

## 検査と目視範囲

`tests/reporting/test_report_appearance.py` は全69頁のfixture被覆、原本hash/再測定一致、書体face・サイズ・インデント・等号・添字基線・白黒・表行高の検査器と負例を検証する。実装側は新PDFから該当する意味役割を選び、`role_errors` / `table_errors` / `monochrome_errors` へ渡す。生成traceを期待座標として渡さない。

測定時に個別目視した代表頁は 0500p1、0600p1/p3/p13/p16/p37、0610p2/p10、0620p14/p15/p16/p17（12頁）と、白紙の0610p8。全69頁は寸法・文字・罫線・グレースケールrender白紙判定まで棚卸ししたが、全頁の詳細目視ではない。新しい帳票は `tests/reporting/test_*_pdf.py` がこれらの検査器で確かめる。

全帳票に共通する規則は次の検査が確かめる。

- `tests/reporting/test_report_spacing.py`：各頁の1行目の基線が97.80pt、見出しの前後が28.56pt、42.84ptの重なった空き行がないこと。
- `tests/reporting/test_report_definitions.py`：「ここに、」の定義で記号が右揃えになり、コロンと「(= 値 単位)」の列がそろうこと。
- `tests/reporting/test_report_equation_terms.py`：代入式の項の列（数値右揃え・演算子中央・間7.44pt、形の違う式は列を共有しない）が行をまたいでそろい、括弧の中で折り返さないこと。
- 各段階の `test_*_semantics.py`／`test_*_pdf.py`：入力票の記号が印刷されないこと、積み分数（Fraction）を使わないこと。
- `tests/reporting/test_frame_report_style.py`：0610/0620系の小表が開いた表（外枠・縦罫なし、合計の上に0.96ptの線1本）であること。
