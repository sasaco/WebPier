#### 組合せの変換方針

`longitudinal_actions.py:172–211` の `combinations[].resolved_components` / `variants` が実際の採用作用である。PDF p7の20×16表は**名目係数**であり、そのままFEMPythonの乗算係数にはできない。

1. 基本ケース1～20はPDFの識別・代表値として保持する。
2. L/Iを含む各組合せは用途別の解決済み荷重ケースを参照し、nativeの係数を1とする。列車も支点モーメントの丸めが係数適用後に行われるため、この処理が必要。
3. 補助ケースは21以降に、family／単複線／用途の固定順で割り当てる。数値が偶然一致しても異なる意味のケースを合体しない。現在の16組合せが使う意味は、L1使用性、L2使用性・安全性・最大、I1使用性、I2使用性・安全性・最大の8つ。原則28荷重・28Define、16Combine、8Pickupとなる。使用性係数が1以外・ρが0になっても意味とID対応を維持する。
4. 基本9～12は帳票対応として残すが、実際のcombineのL/I欄は補助Defineを指す。物理荷重と補助ケース名、元の基本ID、名目係数、解決時の有効係数、実際のcombine係数をprovenanceへ残す。
5. D/WP/S/水平は既存基本の物理荷重×名目係数を使う。変換後に `resolved_components` と一致することを全成分で検証する。
6. Define13～20は `C1=+id,C2=-id`。補助L/Iは正方向だけ。水平の負方向で鉛直荷重・既存偏心Mを反転しない。
7. Combine ID1～16、Pickup ID1～8と所属群はP7 p7～8を保持する。各基本/補助荷重の支持ばねは元基本の `spring_case` を保持する。長短期が混在する組合せは、各ケースの解析結果を重ね合わせるFEMPythonの既存契約を使い、合成荷重1ケース・単一ばねへ置換しない。

**GUIとheadlessの精度差（調査で追加確認）**：現FrameWebforCS GUIのnode、element、fix_node、load_node等は `float?` で保持される。GUI保存・GUI計算用snapshotはSingle値をSystem.Text.Jsonで再直列化する。一方headlessはraw JSONをDoubleで投影し、GUIの型を通らない。Combine係数は現在の両経路でDoubleである。

- .NET10実測で長期Kr `52218663 → Single52218664 → 保存52218664`、短期Kr `104437326 → Single104437328 → 保存104437330`。単に「Single相当の誤差」として無視できない、既知の入力変換境界である。
- nodeの10.3等は内部Single値が変わっても短いJSON表示が10.3へ戻るため、GUI往復の独立期待値は `Q(v)=DoubleParse(JsonSerialize(SingleParse(v)))`。すべてを `Double(Single(v))` とみなすのも誤り。
- 自動生成する正式nativeはP7の正規精度を保持し、headlessでこれを直接検証する。GUI読込/保存は既知Q変換・表示・参照保持を確認し、**GUI保存後も元数値が完全不変とは主張しない**。GUIで保存し直すと付帯JSONの元SHAとは一致しなくなる。
- FEMPython本体のDouble化は今回対象外。元P7数値を厳密に解析へ渡す経路は生成nativeを直接読むheadlessとし、GUIからの計算・再保存はこの量子化を含むことをREADMEと検証記録へ記載する。

#### 照合精度と受入証跡

- ソルバーの反力釣合い・独立加算：力/モーメントについて `abs_error <= 1e-6 + 1e-8*scale`、scaleは独立式の各寄与絶対値の合計。変位の独立式は `1e-10 + 1e-7*abs(expected)`（m/rad）。満たせないときは条件数・荷重投影・丸め・符号を調べ、根拠なく閾値だけ緩めない。

### Risks & Considerations

- **最重要は係数と丸め**：IだけでなくLも用途別解決値を使う。PDF表の320名目係数とnativeの補助ケース用係数が違うことは意図した変換であり、対応表で説明する。
- **支持条件**：Example保存JSONの14/18/20を流用しない。異なる支持ばねの基本解析結果を足す既存手順を維持する。合成荷重を単一ばねに載せる検証で代用しない。
- **荷重点・剛性**：P7節点3/4はExample節点5/6に相当する。梁/柱が現値で同じEでも別材料の入力変更を試験する。有限剛性の剛域についてPDFにない数値を設計根拠として扱わない。
- **既存形状対応**：H1や偏心を含む既存frameを再構築しない。anchor指定のない追加荷重を独自判断で導入しない。既存形状fixtureを使って取込み範囲を明確にする。
- **空荷重**：全空欄load_member行は現runnerが受け付けない。ケースを消してIDを詰める実装も不可。0作用と欠損/無効入力を区別する。
- **出版処理の影響範囲**：2ディレクトリの同時更新が最大の統合リスク。ファイル親内の一時保存・復元と全SHA検証で対応する。プロセス強制終了に対する完全な耐障害トランザクションは今回の既存保証を超えるため、少なくとも世代不整合を成功表示しない。
- **ソフトの版**：FEMPythonは指定ローカルcheckoutを根拠にする。旧Angular保存形式と現runnerの差を混同せず、ソフト更新時には受入検証を再実行する。
- **GUIの単精度**：ソフト内のSingle保持/再直列化によりKr等が変わる。exporterのバグと混同せず、正式native→headlessとGUI往復を別契約で検証する。GUIでP7の全Double値を不変に保持する要件が追加された場合は、外部アプリ改修が必要な別スコープになる。
- **既存作業の保護**：調査時点で多数のstaged変更がある。対象ファイルの最新版を読んで必要箇所のみ変更し、0610/0620の直近修正・入力・以前の試験を巻き戻さない。
