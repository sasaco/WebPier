44. 荷重図（0610 の 8.3、0620 の 9.3）は、同じ生成で作った FrameWeb 入力（`post/線路方向.json`・`post/線路直角方向.json`）を FEMPython（FramePrintPDF）で描き、計算書の PDF に挿入する。0610 と 0620 は同じ経路にする。WebPier 内で荷重図を描く実装（`reporting/figures/loads.py` と 0620 の `_diagrams`）は廃止する。理由：計算書の荷重図が、FrameWeb に渡した荷重そのものの図であるようにするため。
   - 呼び出し：FEMPython 側の `FrameWebforCS.Headless` に PDF の節 `load_diagram` を追加し（FEMPython の責務は FEMPython 側で直す。GridLayoutPdf と同じ扱い）、WebPier の pipeline が子プロセスで `run --pdf-sections load_diagram` を呼ぶ。MCP は経由しない。
   - 荷重図だけを求めるとき（`load_diagram` 以外の節・PIK・CSV なし）、Headless は FEM の計算も Python 環境の起動もしない。荷重図は入力の図であり、計算書の生成に構造解析を持ち込まない。
   - 挿入：FEMPython が出力した荷重図のページを、そのまま計算書のページとして差し込む（流し込みの図として切り出さない。ラスタ化しない）。見本の「複数ケースを1図にまとめ、値を右に並べる」体裁は再現せず、1ケース1図・値は図中の FEMPython の表示に従う。
   - 結合：GridLayoutPdf で描いた計算書と FEMPython の PDF を、WebPier 側が pypdf で結合する。結合は描画を終えた PDF の後処理であって組版ではないので、GridLayoutPdf の責務とはしない。
   - ページ番号：振らない。体裁の見本（`.claude/docs/Example橋脚/output`）はページ番号を印刷しないので、全段階の計算書にページ番号を印刷しない（荷重図を差し込む 0610・0620 も同じ）。
