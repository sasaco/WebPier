# リファクタリングの決定事項（2026-10-18 grill）

監査の指摘に対して決めたことを、決めた順に記録する。原則は docs/adr/ を正とする。

1. 正規の計算経路では元Excelの誤りを直す（ADR-0001）。最初の例ははりハンチ重心 `reaction_weights.py:205`。
2. 元Excelのセル再生をやめて全段階を物理量で計算する。`calculate_*_legacy`・`legacy_audit`・`reaction_report_values` の式評価エンジンを削除する。0610の正規計算と0710は現在 `legacy_audit` に依存しているので、そこを作り直す（ADR-0002）。
3. 元Excel由来の期待値（`*_excel_oracle.json`・`reaction_round_oracle.json` など）は全廃する。Example2 の転記（0600も05/07のPDFから新規に転記）と独立の手計算だけで検証する。多条件の検証も手計算で作り直す。
4. 内部の値を印字桁に丸めて計算する（ADR-0003）。
   - 印字桁は計算器が値ごとに持ち、帳票はそのまま印刷する。
   - 合計は印刷された値の和にする。段階間の引継ぎも印刷された値で行う。
   - 印刷しない中間値は作らない。ただし探索のような反復処理は例外とする。
   - 丸めは四捨五入1種類。Single精度・Excel ROUND・偶数丸め・`macro_handoff_single` は全廃する。
5. 欠けた入力の補完を廃止し、値が欠けていれば入力エラーにする。
   - 全項目が null の枠は空き支承枠として除外する。L3/L4 の null は「その線路なし」とする。
   - B9→B7、f→L1/L2、A/D合計・雪→B/C、支承の null→0、H5/H6/df の null→0、表層の湿潤の null→0 をすべて廃止する。
   - GUI に「B7と同じ」「B/Cと同じ」ボタンを置き、明示的な値として書き込む。
   - 未知の土質区分は入力エラーにする。
   - 既存の `pre/input.json` は一度だけ移行する。
6. 車両名は選択式にする。
   - 選択肢の一覧はプログラムが持ち、入力JSONには選んだ値だけを保存する。
   - 当面の一覧は `EA-17`（EA-17の規定式）と `P-16`（軸重式）。一覧にない値は入力エラーにする。
   - `杭種`・`場所打ち杭の施工条件`・`土質区分` も同じ方式にし、入力JSON内の `選択肢` は削除する。
   - 制動の式を選んだ理由を計算書に印刷する。
7. ソースは層別パッケージ（core/inputs/calc/reporting/export/gui ＋ pipeline の StageSpec 登録表）にする。依存の向きは境界テストで強制し、`*_report.py` の中継ファイル6本は削除する（ADR-0004）。
8. GridLayoutPdf へ汎用機能を移す（CLAUDE.md の規則による）。対象は keep-with-next、折り返しのある表のセル、破線、塗りつぶし、0.12pt 格子の列幅、IndentTo/Leading。移したあと WebPier 側の複製は削除する。
9. 生成物と作業記録の扱い
   - `output/`・`post/` は git の追跡をやめる。`*.bak` は削除して ignore に入れる。
   - `tools/build_reaction_report_layout.py` と `src/assets/reaction_report_layout.json` は削除する。
   - 前提が崩れた `.claude/docs/research`・`plans` は削除し、有効な結論は ADR・README へ移す。
   - JRSNAP の受入は最後に、実アプリ（5.2-L03、スキル `jrsnap-input-open-save`）でやり直す。古いスナップショットと evidence は削除する。それまで受入テストは失敗のまま見える状態にし、skip にはしない。
11. 可動支承の水平力の下限は摩擦係数 μ を使う（μ·T/n）。元式の互換動作ではなく正しい設計式として扱い、README の互換一覧から外して本文の規則として書く。
12. 0620 の橋脚への風荷重
   - 部材ごとの実際の受風幅を使う。はりは b1、ハンチは b1 から下面幅（b1−b4−b5）への台形、柱は b6。
   - 地表面（フーチング天端 + min(df1, df2)）より上だけに載荷する。いまのコードはフーチング天端まで載荷しているが、Example2（9-12、8-28 の Df−H6=1.080）は地表面より上だけ。
   - 計算書には受風高さと区間ごとの幅を印刷する。
13. 複線の衝撃低減 `1 − L/200` は、L ≥ 200 m（係数 ≤ 0）を入力エラー（適用範囲外）にする。推測による範囲は設けない。式と L を計算書に印刷する。
14. 質問を待たずに直すもの（自明）
   - CLI は `--jrsnap` の有無にかかわらず、常に厳密な JSON 解析（重複キー・NaN・Infinity を拒否）を使う。
   - `GenerationOptions.stage` の既定を CLI と同じ "all" にそろえるか、既定を持たない必須の引数にする。
   - 表層厚の警告の完全一致比較を許容差つきの比較にする。
   - `test_column_rebar_ui::test_dialog_setup_failures_release_grab_and_preserve_draft` の実行順序依存を直す。
15. テストの合格基準を層ごとに決め、`check.ps1` で強制する。
   - 行・分岐カバレッジの下限は core/inputs/calc/export/pipeline が 100%、reporting が 95%、gui が 85%。
   - 印刷物での検算テストを入れる。PDF の数値を読み取り、印刷された部分の値から合計・積を再計算して、全頁で一致を確かめる。
   - `hypothesis` による性質テストを入れる。

   - 入力JSONの形式は直接書き換え、移行の道具や旧形式の読み替えは作らない。`pre/input.json` とテスト用入力は新しい形式で書き直す。

17. 入力値は入力時に印字桁へ丸める。
   - GUI は入力した時点で丸め、入力JSONには丸めた値を保存する。
   - 手で編集したJSONに印字桁より細かい値があれば、計算時に入力エラーにする（黙って丸めない）。
   - `pre/input.json` の重心高 hs（2.9520833…）などは、丸めた値に書き直す。
18. 土質区分の選択肢は「砂質土」「砂礫」「粘性土」「砂質土と粘性土の互層」の4つ（当初「岩盤」としたが、Example2 04 p.4-1 で 5.1 / −3/4 は互層の式と分かり訂正）。区分と係数・指数を計算書に印刷する。岩盤は式とともに将来追加する。
19. 杭（杭種・場所打ち杭の施工条件・杭の配置・単位体積重量.杭）、斜角、遠心の作用方向は、近い将来の機能追加のため入力欄を残す。

   - 杭種は選択式（直接基礎・場所打ち杭）。直接基礎以外を選ぶと「未対応」の入力エラーにする。
