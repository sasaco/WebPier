44. 荷重図（0610 の 8.3、0620 の 9.3）は、同じ生成で作った FrameWeb 入力（`post/線路方向.json`・`post/線路直角方向.json`）を FEMPython（FramePrintPDF）で描き、計算書の PDF に挿入する。0610 と 0620 は同じ経路にする。WebPier 内で荷重図を描く実装（`reporting/figures/loads.py` と 0620 の `_diagrams`）は廃止する。理由：計算書の荷重図が、FrameWeb に渡した荷重そのものの図であるようにするため。
   - 呼び出し：FEMPython 側の `FrameWebforCS.Headless` に PDF の節 `load_diagram` を追加し（FEMPython の責務は FEMPython 側で直す。GridLayoutPdf と同じ扱い）、WebPier の pipeline が子プロセスで `run --pdf-sections load_diagram` を呼ぶ。MCP は経由しない。
   - 荷重図だけを求めるとき（`load_diagram` 以外の節・PIK・CSV なし）、Headless は FEM の計算も Python 環境の起動もしない。荷重図は入力の図であり、計算書の生成に構造解析を持ち込まない。
   - 挿入：FEMPython が出力した荷重図のページを、そのまま計算書のページとして差し込む（流し込みの図として切り出さない。ラスタ化しない）。見本の「複数ケースを1図にまとめ、値を右に並べる」体裁は再現せず、1ケース1図・値は図中の FEMPython の表示に従う。
   - 結合：GridLayoutPdf で描いた計算書と FEMPython の PDF を、WebPier 側が pypdf で結合する。結合は描画を終えた PDF の後処理であって組版ではないので、GridLayoutPdf の責務とはしない。
   - ページ番号：振らない。体裁の見本（`.claude/docs/Example橋脚/output`）はページ番号を印刷しないので、全段階の計算書にページ番号を印刷しない（荷重図を差し込む 0610・0620 も同じ）。
   - 配置：計算書の原稿を挿入位置で2つの文書に分けて描く。前半は荷重図の節の見出し（「8.3 荷重図」「9.3 荷重図」）までで、見出しは流れの中に置く（前の節の最終ページの余白に入ってよい）。後半は次の節（組合せ）から新しいページで始める。結合は「前半＋FEMPython のページ＋後半」とする。荷重図の節には説明文を書かない（0620 にある符号の説明文も削る）。前半の末尾の見出しは、見出しの書体の段落として組む（GridLayoutPdf の Heading は同じ文書の次のブロックを伴う必要があり、ここで伴うのは FEMPython のページだから）。
   - 体裁の指定：WebPier は A4 縦、軸線図のページなし、1ページに2ケース（上下に分割）を指定する。書体の大きさ・縮尺は FEMPython の既定に任せる。Headless の `load_diagram` にこれらを渡す引数を設ける。
   - 対象：FEMPython には公開する `post/*.json` と同じバイト列を渡し、その全荷重ケースを描く。基本ケースのほか、FrameWeb のためだけに加えたケース（使用性の衝撃 `I1s` など）も描く。WebPier は荷重ケースを間引かない。
   - runner の場所：リポジトリのルートの `.env`（追跡しない）の `STRUCTURAL_MCP_FEMPYTHON_RUNNER` に Headless の exe の絶対パスを書く（structural-mcp と同じ変数名）。プロセスの環境変数に同じ名前があればそちらを優先する。未設定・存在しない・起動できないときは、0610・0620 を含む生成を入力エラーと同じく止める。荷重図を省いて続ける経路は作らない（決定42と同じく opt-in にしない）。
   - 実装の同一性：runner のバイナリは `dependency_hashes` に入れず、付帯JSONには runner が返す `engineVersion` だけを記録する（開発ビルドでは同じ版番号のまま中身が変わりうることを受け入れる）。結合に使う pypdf は実行時依存に移し、ReportLab と同じく `dependency_hashes` に入れる。
   - 決定性：FEMPython の出力（荷重図の PDF の中身・ページ数・体裁）は FEMPython の責務とし、どんな状態でも WebPier は受け入れる。毎回同じバイトになることも求めない。したがって 0610・0620 の計算書は、荷重図のページを含めると毎回同じバイトになるとは限らない（CLAUDE.md の「PDF は毎回同じバイト」の例外）。WebPier が描いた部分（前半・後半）と結合の手順は従来どおり決定的にする。
   - テスト：通常のテストは、Headless と同じやり取り（`run` の引数、stdout の envelope、`protocolVersion`、出力先の成果物）をまねる代役の runner を使い、決まった数ページの PDF を返させる。結合・順序・付帯JSON・失敗時の停止はこれで厳密に確かめる。本物の runner を呼ぶテストは1つだけ置き、`.env`（または環境変数）が設定されているときだけ実行して「動いて挿入される」ことだけを確かめる。FEMPython のやり取りが変わったら代役も合わせて更新する（本物のテストの失敗がその合図）。
   - FrameWeb 入力の y の向き：FEMPython（FrameWebforCS/Headless・FramePrintPDF）は保存形式を現行形式（`ver` 2 以降、y は下向き）として扱うので、旧形式（y 上向き、Example2 の保存ファイル）のままでは荷重図が上下逆さまに描かれる。WebPier の FrameWeb 出力は節点の y、節点荷重の ty・rz、部材荷重の gy の符号を反転して書く（tx・gx はそのまま）。橋脚を上下に鏡に映しただけなので解析結果は同等で、荷重図を描かせて向き（N・P は下向き、H・風は +x、M は計算書と同じ符号）を確かめて決めた。`ver` は書かない。FrameWebforJS（ブラウザ版）は `ver` のないファイルを旧形式として y と荷重をもう一度反転するので、ブラウザ版で開くと上下逆になる。

45. 計算書の体裁は見本 `.claude/docs/Example橋脚/output` に合わせ、`.claude/docs/reporting-style.md` を正とする（1行目の基線 97.80pt、頁番号なし、行送り 14.28pt、見出しとまとまりの前後の空き1行、代入式の項の列揃え、横書きの分数、「ここに、」の定義リスト）。入力票のセル記号（B1〜B9、H1〜H6、W3〜W9、df1、df2）は計算書で定義されていないので印刷しない。式は値の代入式にするか、計算書の中で定義した記号で書く（風荷重の W1/W2 は設計記号なので使う）。汎用の組版機能は GridLayoutPdf に足した（TermStop、Spacer の頁頭破棄、Leading の overhang）。手順はスキル `pier-report-style`。
