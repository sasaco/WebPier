## Implementation Plan: Omit Zero Volume Girder Support

> 実装済み（2026-10-16）。ユーザーの「SHAとか必要か？シンプルに実装」に従い、以下の詳細ゲートは実行手順としては取り下げ、描画帯切替・関連テスト・目視確認・0600再生成に絞った。V=0の省略、後続連番、上詰めを実装し、印字関連22件成功。既存CLIテスト1件の現入力と固定期待値の不一致は、省略変更なしでも再現。なお正の寸法が面積ROUNDで0になる入力は既存計算でInputErrorとなり、当初想定した描画ケースではなかった。

### Purpose
0600「(3) 橋脚自重の計算」で、桁受けの計算済み体積 V が0の場合に「1) 桁受け」の見出し・計算式・寸法図を印字しない。後続項目は1から連番とし、はりの計算一式を上詰めして、図表の分断・重複・欠落がない改ページを維持する。

### Scope
- New files: 製品ファイルの追加なし。必要な検証資料は `tmp/pdfs/omit-zero-volume-girder-support/` に保存する。
- Modified files:
  - `src/reaction_report_pagination.py`: 体積ゼロ時だけ、原本4頁の描画対象を「はり」の帯へ変更する。
  - `src/reaction_report.py`: 計算済み体積から省略条件を渡す。既存の水平荷重描画経路を保持する。
  - `./tests/test_reaction_report.py`: 省略・連番・描画位置・非ゼロ・境界条件・反復描画の回帰検証を追加する。
  - `./output/0600_上部工反力.pdf` および `.json`: 検証完了後、現在の入力で再生成する。ユーザー確認済み。
- Dependencies: 既存のReportLab、pypdf、PyMuPDF、pytest、`uv`。追加ライブラリや実行時Excelは不要。
- 対象外: 計算式・丸め規則・入力値・入力GUI、(4)(5)の重量・重心集計表の桁受け行、全体図、0500/0610/0620の成果物、共有 `_Report` / `WIDTH`。現在の入力から再計算するため保存済み0600 JSONとの数値差は生じ得るが、今回の改修前後で同じ入力を計算した結果は同一とする。

現状調査の根拠:

- `reaction_weights.py:267-275` は桁受け体積を `result["weights"]["cells"]["X63"]` に格納する。これは表示丸め前の計算済み体積で、面積には既存ROUNDが適用済み（同`:105-110`）。寸法から体積を別途再計算しない。
- `assets/reaction_report_layout.json:1` の見出し番号式は `E81=IF(X$63>0,E61+1,E61)`、以後 `E109/E135/E163/E199` が連番。ゼロ時は既に「1) はり、2) 柱、3) フーチング、4) 載荷土、5) 浮力」となるため、番号式の改修は不要。
- `reaction_report_pagination.py:51-62` は原本4頁の `(4, 86.28, 755)` を描画する。はり開始座標は372.48。`reaction_report_diagrams.py:424-430` の桁受け図は202～350、はり図は604～750。
- `reaction_report_pagination.py:120-142` の平行移動、`reaction_report_layout.py:219-223` のセル境界検査、`reaction_report_diagrams.py:439-470` の図全体包含判定を再利用する。
- `reaction_report.py:83-89` は `pages[:13]` / `pages[30:33]` を使う。`tests/test_reaction_report_snow.py:132-133` は引数なし `report_pages()` を利用する。どちらも互換性を維持する。
- 既存保存PDFは34頁。3頁は全体図、4頁は桁受け＋はり、5頁は柱＋フーチング。4頁の桁受けはV=0でも印字されている。調査時SHA256: `55d83f8495237859db12956ea19cd85b68ccb964b5e814fbe0bf3787ebb467d6`。
- 保存済み0600 JSONの入力SHAは `73c4d7c4fb3a...`、現在入力は `af2663793545...`。旧JSONには現在の水平荷重描画が必要とする `longitudinal[].combination` もない。旧JSONを新rendererへ直接渡した全体再描画は行わず、現入力から計算する。

### Implementation Steps

同一入力の基準保存と失敗する回帰テストの確認を先に行い、描画帯の切替、回帰検証、成果物更新と最終ゲートの順で進める。

#### Step 1: 同一入力による比較基準と対象範囲を確保する
- [ ] 実装開始時のgit差分、入力と既存成果物のSHAを記録し、現在存在する未コミット変更を保護する。入力は検証期間中のスナップショットを使用する。
- [ ] 修正前の現在の作業ツリーで、その入力から0600を一時出力先へ生成し、PDF・JSONを変更前基準として保存する。既存保存PDFは見た目の参考とし、今回の変更差分判定には同一コード世代・入力の基準を用いる。
- [ ] 既存fixture `pedestal_nonzero` でも変更前PDFを保存する。ゼロ時・非ゼロ時の `(3)` の番号とページ境界を記録する。
- [ ] 製品コードの修正前に、Step 3に列挙した条件の対象回帰テストを `test_reaction_report.py` に追加する。既存APIを通した省略・上詰めの期待が、旧実装では実際の桁受け残存によって失敗することを確認する。新APIがまだないことによるImportError等を期待する失敗として扱わず、旧コードへ戻す操作はしない。
**Verification**: 本番入力・出力のSHAが変わらず、一時JSONの入力SHAがスナップショットと一致する。ゼロ時の詳細に桁受けが存在する現象と、非ゼロ時の従来描画を再現できる。省略テストは期待した理由で失敗し、非ゼロ維持・欠損値エラーの既存動作を記録できる。以後の比較対象が古い保存JSONではないことを確認する。

一時生成には、既存CLIの `--input` と `--output-dir` を用いる。例（非ゼロfixtureも同様に一時JSONから生成する）:

```powershell

```

改修後の候補は同じコマンドで出力先だけ `after` に変え、最終公開と同一の計算・描画経路を使用する。

#### Step 2: 体積ゼロ時の描画帯を切り替える
- [ ] `X63 == 0` の場合だけ省略する。重量N、印字文字列、許容誤差、寸法の独自再計算は判定に使わない。必要な計算値が欠けた場合の既存エラーを、ゼロの既定値で隠さない。
- [ ] `report_pages()` に省略可否を受け取るキーワード引数を追加し、引数なしは従来構成とする。呼出元はX63から省略可否を渡す。
- [ ] 省略時の第4ページを「はり」だけの `(4, 372.48, 755)` とし、既存処理で本文上端 `PAGE_TOP=56` へ移動する。非ゼロ時は従来の `(4, 86.28, 755)` を使う。
- [ ] 第5ページの柱＋フーチング、後続のページ構成、文字・罫線・図の大きさ、テンプレートの番号式、共有描画部品を保持する。テンプレートやresultを破壊的に変更しない。
**Verification**: 解決した描画帯がはりの全セル・表・図を包含し、桁受けのセル・図と交差しないことを座標で検証する。帯を横切るセルのエラーがなく、本文高さは730以内。非ゼロ時と引数なしのページ定義は従来どおりで、後続ページのインデックスはずれない。`reaction_report.py` の今回の差分がX63取得・フラグ受渡しに限られ、既存の水平荷重描画経路を失っていないことを確認する。

#### Step 3: 省略・番号・改ページの回帰を検証する
- [ ] Step 1で追加したテストを実行する。ゼロ条件はB3=0、W3=0、H1=0を個別に、さらに全寸法が正でも既存の面積ROUNDでX63=0になる条件を検証する。通常の非ゼロfixture、微小な正のX63で表示V=0.000/N=0.00になる条件、体積が正で単位重量が0の条件も扱う。入力は一時コピーで変更する。
- [ ] X63を欠損させたresultで、既存の計算値不足エラーを維持し、ゼロと見なした省略PDFを生成しないことを対象関数レベルで確認する。引数なし `report_pages()` の従来互換もテストする。
- [ ] PDF全体の単語検索に依存せず、`(3)`～`(4)` の詳細範囲で桁受け見出し・式・図が省略されることを確認する。ゼロ時は番号1～5、非ゼロ時は桁受けを含む番号1～6が各1回・正順に現れることを確認する。
- [ ] はりの見出しが本文上端へ移動し、表・結果・寸法図が同一頁に完結することを検証する。既存 `_filled_circles` を再利用して対象頁の重心マーカーがゼロ時2個、非ゼロ時4個であることを確認する。集計表の桁受け行は残る。
- [ ] ゼロ→非ゼロ→ゼロを同一プロセスで描画し、result・キャッシュ済みレイアウトの不変性、最初と最後のゼロ描画の一致を確認する。
- [ ] 同じ入力の変更前後でJSON計算結果が同一、ゼロ時は対象頁以外のページ別文字・位置・描画が同一、非ゼロ時は全頁の描画が同一であることを検証する。PDF全体のオブジェクト番号差ではなく、正規化した内容・座標または同一条件でのページ画像で比較する。
**Verification**: Step 1で省略漏れを検出したテストを含め、対象テストがすべて合格する。既存の柱＋フーチング同頁、土・水の表と図の同頁、水平荷重の順序と計算一式を保持する。現行34頁のケースは34頁を維持し、他の入力でも今回の変更でページ数が変わらない。

### Risks & Considerations
- はり382.52＋間隔12＋柱336.32＝730.84で本文高さ730を超える。ページ削減のために縮小・余白変更・柱の移動を行わず、既存のページ区切りを維持する。
- X63は既存面積ROUNDを含む計算済み体積であり、すべての計算途中が未丸めという意味ではない。表示Vや重量Nが0でもX63が正なら省略しない。
- レイアウトJSONはキャッシュされる。値や図を削除する実装ではなく、描画帯の選択で省略する。採番式も再実装しない。
- `reaction_report.py`、計算入力・水平荷重関連などには開始前から未コミット変更がある。HEADではなく現在の作業ツリーを比較基準にし、reset・まとめての復元・commitを行わない。
- 古い保存JSONからの全体再描画は、現在の水平荷重rendererに必要なキーの欠落を無音で誤解釈し得る。必ず現在入力から既存CLIで再計算する。
- Python実行は明示的なK:作業ディレクトリとUTF-8を使用する。UNC経由のネイティブDLL読込問題やPowerShellパイプの日本語文字化けを避ける。
- `.agents/rules`、`.agents/STATE.md`、`PROGRESS.md`、`.agents/docs/DESIGN.md` は未作成であることを報告済み。存在しない規約を補作せず、本計画では実コードと確認済み仕様を根拠とする。
- Codex分解相談: `.agents/logs/codex/20261016T003706Z-plan-omit-zero-volume-girder-support-steps.md`。その後判明した保存成果物と現入力の差異、およびユーザーの再生成方針を本計画に反映した。
