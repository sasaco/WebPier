### Purpose

「05 計算・印刷」のPDFプレビューを、左サイドバーに帳票一覧を持つモーダルダイアログへ移す。下方向のスクロールで同じPDF内のページを読み進め、最終ページの末尾からは一覧の次のPDFへ自動で進めるようにする。

### Scope

**画面と操作の採用案（本計画の承認対象）**

- 主画面には入力・出力先、計算実行ボタン、進捗、計算結果・エラーログと「PDFプレビュー」ボタンを残す。埋込みビューアーとPDF選択コンボボックスをダイアログへ移す。
- 「PDFプレビュー」で開くほか、計算・4 PDF＋4 JSONの検証が正常終了したときに自動で開く。計算画面を選んだだけでは開かず、計算失敗時は自動で開かない。失敗後の残存PDFはボタンから明示的に確認できる。
- 左側にPDF一覧と「一覧を更新」、右側に現在のPDF名、前後ページ・ページ数・倍率・幅合わせ・再表示とPDF表示領域を置く。一覧は主画面側の既存規則で並べ、ファイル名と「今回の計算結果／既存出力・今回未計算」を区別して表示する。長い日本語名と多数のPDFは一覧側でスクロール可能にする。
- 一覧の正体は `Path` とし、ラベル文字列からファイルパスを復元しない。再読込時は既存選択を優先し、計算成功後は既存仕様どおり生成対象の選択を優先する。閉じても最後の選択ファイルをアプリ側に保持し、再度開いたときはそのPDFの先頭ページを表示する。
- 同一アプリのダイアログは1個。再度開く要求は既存ダイアログを前面にする。親に対する `transient` とローカルgrabで主画面の操作を抑止し、ダイアログ内には計算実行操作を置かない。閉じるボタン・Escape・ウィンドウの×で閉じ、親へフォーカスを戻す。
- ダイアログはリサイズ可能とし、親の位置・利用可能な画面寸法を考慮して表示する。1360×900と980×640の環境で左一覧・右ビューアー・操作列を同時に利用できることを確認する。
- PDFが0件でもダイアログは開ける。空状態を説明し、「一覧を更新」と閉じる操作を残す。計算中は開く操作を無効にする。

**スクロールの具体的な仕様**

末尾の内容が読めるよう、下端へ到達した操作ではその表示を維持し、**下端からさらに下へスクロールしたとき**に自動で進む。ファイル切替のためのボタン操作は不要とする。

| 操作・状態 | 動作 |
|---|---|
| 現在ページの途中で下方向ホイール／縦スクロール | 通常スクロール。下端に到達しても末尾の内容を表示して留まる |
| 下端でさらに下方向、PDF内に後続ページあり | 同じPDFの次ページの先頭へ進む |
| 最終ページの下端でさらに下方向、後続PDFあり | 左一覧の次のPDFを選び、先頭ページの先頭へ進む |
| 一覧の最後のPDFの最終ページの下端 | その位置に留まる。先頭PDFへ戻らない |
| ページ全体が表示領域に収まる | 表示しただけでは進まず、新しい下方向操作で1ページ／1ファイルだけ進む |
| 縦スクロールバーのつまみ移動 | 現在ページ内の位置だけ変更。つまみを末尾へ移動しただけでは切り替えない。下端での下向きステップ／ページ操作は自動送りの対象 |
| 上方向、横スクロール、Shift＋ホイール、一覧側のスクロール | ページ／PDFの自動送りをしない |
| リサイズ、倍率・幅合わせ、再表示、一覧更新、プログラムからの位置変更 | 自動送りをしない |
| 描画待ち・画像なし・読込エラー・閉じた後 | 自動送りをしない |

- 前ページ・次ページボタンは現在のPDF内だけで動作する。上方向への自動ページ送り・前PDFへの自動切替は追加しない。
- 1操作で複数ページ／PDFを飛ばさない。大きいホイールdeltaの余りを次ページへ持ち越さず、描画中の操作と同じホイール連続入力の残りで次々に進むことを防ぐ。最後の縦入力から250ms途切れ、次のページの表示も完了してから、新しい下方向操作を受け付ける。無視した残余イベントでも最終入力時刻を更新し、同じ入力群の途中で受付を再開しない。250msのタイマーだけでページを進めることはない。
- 全ページ・全PDFを縦につないで画像として保持しない。既存の1ページ描画を使い、ページ境界で表示を切り替える。
- 次のPDFが削除・破損・読込不可なら、その項目を選択した状態でエラーを表示して停止する。自動で飛ばしてさらに次へ進まず、「再表示」または手動選択で復帰する。

### Implementation Steps

誤送りの危険がある入力境界を先に確定し、ダイアログ単体、主画面との連携、回帰確認、画面確認の順に進める。検証には一時入力・一時出力を使う。

**Step 1・2の実装に先立って固定する接続契約**

- 文書末尾のcallbackは同期的に「次の `Path` または `None`」を返す。ダイアログは現在の一覧スナップショットから次を決め、一覧選択・右側の名前・ホストの選択パスを更新するが、そのcallback内から `show_pdf()` を呼ばない。`PdfPreview` が返されたPathを1回だけ読み込み、同じ入力群の抑止状態を引き継ぐ。`None` なら末尾に留まる。
- 手動のファイル選択も同じ選択更新経路を使い、その後に1回だけ `show_pdf()` を呼ぶ。ホストへの選択通知は `Path` の記録だけとし、再描画を呼ばない。
- アクセス／freshness通知は同期の状態・ラベル更新専用で、一覧走査、選択変更、`show_pdf()`、reloadへ再入しない。
- 一覧更新要求はホストが走査・順序・結果ラベル・選択維持／代替選択を決め、新しい一覧スナップショットを返す。ダイアログは古い描画・操作を無効化してから反映し、選択を1回だけ読み直す。閉じる通知はホストのダイアログ参照を解除し、重複通知しても安全とする。
- 縦Scrollbarの `moveto fraction`、`scroll N units`、`scroll N pages` を受け付ける。`moveto` は位置変更のみ、正の `scroll` はホイールと同じ下端判定、負の `scroll` は現在ページ内の上方向移動とする。
- 自動送り用の最終入力時刻と抑止状態は通常のrender状態から分ける。無視した縦入力も250msの休止判定を延長する。ダイアログ単体テストは一覧更新・選択・freshness・終了のcallbackをfakeで与え、主画面の実装に依存させない。

### Risks & Considerations

- **末尾の読み飛ばし**: 下端を初めて表示した瞬間に切り替えると末尾の文章が読めない。採用案は下端からの追加の下方向操作を遷移条件とし、ボタンなしで次へ進める。
- **ページ末尾とPDF末尾の混同**: Canvasは1ページだけを描く。最終ページ以外は同じPDFの次ページへ進め、ファイル送りは最終ページだけから要求する。
- **連続入力と再描画**: 描画完了だけで遷移を再受付すると、慣性ホイールの残りで短いPDFを飛ばす。描画待ち・最後の縦入力から250msの休止・操作世代を組み合わせ、1入力群で複数境界を越えないことを検証する。無視したイベントも休止判定を延長し、自動PDF切替では抑止状態を維持する。250msはテスト可能な定数とし、操作感の調整時は境界テストも再実行する。
- **モーダルと計算状態の結合**: 現在の更新処理にはpreview不在での早期returnがある。busy・ログ・freshnessをdialogから独立させる。計算完了をダイアログ生成の成功に依存させない。
- **freshness更新の再入**: アクセスcallbackで一覧を再読込すると同じビューアーへ再入する。計算状態とラベルだけ更新し、現在パス・スクロール位置・描画予約を変えない。
- **リソースとWindowsファイル置換**: 既存のwithによるPDF解放、1画像の保持、3000px／600万画素の制限とメインスレッドでのPyMuPDF処理を維持する。全ページの先読みやPDFハンドルの常駐は行わない。
- **grab・focus・callbackの取り残し**: 通常close、親破棄、構築失敗を同じcleanup契約にまとめる。globalな `unbind_all` により入力画面やtksheetの操作を壊さない。
- **検証範囲**: 本文のテスト・画面確認は実装時の受入条件として完了した。計画作成時の構造・実在・Codexレビューと、実装後の製品テスト・画面確認の証拠は区別して記録する。
