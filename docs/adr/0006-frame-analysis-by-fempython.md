# 骨組解析は FEMPython、柱の断面照査は Capacita に任せ、基礎の安定計算は WebPier で行う

これまで WebPier の範囲は、FrameWeb 入力（`post/線路方向.json` など）を作るところまでで、構造解析と部材照査は対象外だった。0610・0620 の照査（Example2 の 08・09 の 8.5 以降）に着手するにあたり、範囲を次のように分ける。

- **骨組解析**：FEMPython が行う。WebPier は生成した FrameWeb 入力をそのまま Headless runner に渡し、ピックアップ断面力・変位量・反力のファイルを、返ったままの形で `post/` に公開する。
- **柱の断面照査**：Capacita（RcDan）が行う。WebPier は WDJ を作って計算させる。
- **基礎の安定計算**：WebPier の `calc` が、0500 と同じく橋脚固有の計算として行う。

WebPier はピックアップのファイルを設計応答値として読む。読むのは返った値そのもので、取り込むときに印字桁へ丸める（ADR-0003）。解析式と RC 断面照査の式は WebPier で再実装しない。汎用の計算エンジンをそれぞれのリポジトリに集め、同じ式を二重に持たないためである（ADR-0005 と同じ扱い）。寸法と配筋の最適化は引き続き対象外とする。

## Consequences

- 解析結果の中身・形式・決定性は FEMPython の責務とする。WebPier は付帯JSONに `engineVersion` を記録し、結果のバイトを実装の同一性（`dependency_hashes`）に結び付けない。Headless は結果を `engineeringStatus: "not_checked"` として返す。
- 荷重図だけを描く通常の生成（決定44）には、構造解析を持ち込まない。骨組解析は、利用者が選んだときだけ、同じ生成の中で行う。ピックアップのファイルは、同じ生成の他の成果物とまとめて公開する。
