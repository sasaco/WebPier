# 0711・0721 の計算書は Aggre-SE の帳票そのものにする

0711・0721 では、静的非線形解析の結果と耐震照査の入力（決定49の XML）を Aggre-SE（structural-mcp の `Batch`、Docu-SE）の Headless runner で計算させる。runner が返した `report.pdf` を、バイト列のまま 0711・0721 の計算書として公開する。WebPier は見出しも節の番号も描かず、ページの選択や並べ替えもしない。見本の 10.5・10.6 は、Aggre-SE の帳票に作成者が見出しを書き込み、Case ごとに総括表と JRSNAP の基礎照査の出力を挟んだものだった。ここで再現しないのは、見出しだけのページを足すか、他のプログラムのページの中身を書き換えるかのどちらかになるからである（ADR-0005 は中身の書き換えを禁じている）。応答値の算定・損傷レベル・基礎の安定の照査の式と表は、Aggre-SE の責務として二重に持たない（ADR-0006・0008 と同じ分担）。0611 のように WebPier が見出しを描き、そこへ差し込む案は、見出しだけのページが Case ごとにでき、利益がないので採らなかった（owner 2026-10-19）。

## Consequences

- 0711・0721 の計算書には、他の段階と違って節の番号（10.5・10.6）がなく、Aggre-SE の書式（1ページ目の見出しは NDU の題名と DB1 の名前、A3 横のページを含む）で印刷される。見本にない安全率一覧表も入る。
- Aggre-SE の runner は照査値も OK/NG も返さないので、WebPier は照査を実行したこと（`engineeringStatus: not_evaluated`）だけを記録する。判定は計算書で人が見る。NG でも生成は止まらない。
- 計算書のバイト列は Aggre-SE の責務で、同じ入力でも毎回同じになるとは限らない。
- 直接基礎の照査の抵抗側は、JRSNAP の基礎照査の出力（`_Output_Chokukiso.csv`）がない間、Aggre-SE が DB1 から求めた値になる（決定49の既知の差）。
- 細目は `.claude/docs/plans/refactoring-decisions.md` の決定56。
