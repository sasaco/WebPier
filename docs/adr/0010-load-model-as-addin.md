# 死荷重以外の支承作用と作用の組合せは、荷重モデルとして差し替える

LRT の P7橋脚では、列車荷重のかわりに車荷重が載り、その反力・水平力は支承ごとの指定値で来る。地震時の上部工の慣性力・活荷重慣性力も指定値で来て、作用の組合せも車荷重用になる。決定69（雪のない橋脚）のように、案件の条件ごとにアプリへ分岐やオプションを足していくと、管理できなくなる。そこで、橋脚に作用するものを「支承を通って来る死荷重以外の作用」と「それ以外」に分け、前者を **荷重モデル**（CONTEXT.md）として差し替えられるようにする（owner 2026-10-20）。荷重モデルが与えるのは、次のものである。

- 支承作用（基本ケースごと・支承ごとの鉛直力、線路方向と直角方向の水平力、作用高さ）
- 基本ケースごとのふるまい（地盤ばねの区分、静的非線形解析での固定・増分と向き）
- 骨組・地震時・片持ち梁の作用の組合せと、抽出ケースへの割り当て

アプリが持つのは、次のものである。

- 死荷重（D1・D2）・浮力・躯体の風・橋脚自重の慣性力
- 支承作用から骨組や片持ち梁の荷重への変換
- FrameWeb・NDU、各 runner、照査
- 抽出ケースの区分
- 計算書の全体

案件の荷重モデルは、案件の repo に置くアドインとし、`--addin` で WebPier が読み込む。いまの列車荷重も、同じ約束の上で動く標準の荷重モデルに作り直す。これは、通り道を1本にし、約束が足りていることを Example橋脚2 で確かめるためである。

## Considered Options

- **作用ごとのオプションを入力に足す（決定69の延長）**：車荷重・指定値の慣性力・独自の組合せまで広げると、アプリが案件の事情を抱え込む。採らない。
- **案件の repo に起動用のスクリプトを置き、段階の一覧（Registry）を組み替えて `generate()` を呼ぶ**：MCP の経路と入力エディタがそのスクリプトを通らないので、同じ入力が経路によって別の荷重モデルで計算される。採らない。
- **列車の通り道を残し、アドイン用の通り道を足す**：下流に列車かアドインかの分岐が残り、2本の通り道がずれていく。採らない。
- **0610 などの計算書をアドインが丸ごと書く**：印字桁・荷重図・頁の組み方をアドインごとに作り直すことになる。また、解析に渡したデータと計算書の一致をアドインが保証しなければならない。採らない。アドインは荷重の値の根拠の節だけを書く。
- **アドインの入力ファイルをアプリが読み出し口で管理する、`input.json` にアドインの目印を書く**：アプリは自分の責務の範囲だけを見る（owner）。採らない。

## Consequences

- `--addin` を付けるのは、呼び出す側の責任になる。付けずに流すと、エラーにならずに標準の荷重モデル（列車）で計算される。
- アドインをつないだとき、`input.json` の荷重モデルに属する項目は無視される（検査も印字もしない）。入力エディタはアドインに対応しない。
- アドインの入力とその来歴は、アドインの責任になる。アプリは、アドインが申告した名前・版・来歴を、解釈せずに成果物の来歴に写す。
- 抽出ケースの区分に組合せがなければ、断面力0のケースとして通る。ゼロ割りになる照査（基礎の照査など）は、その区分を名指しした入力エラーにする。
- 列車を前提にした箇所を作り直す改修が大きい（20個の `BasicCase`、決定69の分岐、NDU の検証器のケースの名前と並び、計算書の基本ケースの表）。
- 片持ち梁の組合せは Capacita の断面力の表の8行に割り当てる（5区分ではない）。0720 の制御節点の重みは、増分の地震時ケースの直角方向の支承作用を起点側・終点側ごとに合計したもの（owner 2026-10-20）。
- 細目は `.claude/docs/plans/refactoring-decisions.md` の決定70。差し込み口と約束（①）は `webpier/loadmodel/`・`webpier/calc/generic/`・`webpier/reporting/stages/generic/`・`webpier/pipeline/addin.py`、使い方は README の「荷重モデルのアドイン」。
- 約束の版 2（決定118、2026-10-28）から、アドインは荷重モデルとは別に、柱の計算上断面（CONTEXT.md）も与えられる。荷重モデルの定義は広げず、アプリの持つ柱の断面のうち、RC 断面として扱うところだけを差し替える。
