# 作る計算書は入力の出力項目だけで決める

作る計算書は、入力 `outputs`（**出力項目**、CONTEXT.md）の12の項目だけで決める。コマンド（`python -m webpier`）、headless の runner、structural-mcp の `webpier_generate`、入力エディタのどれでも同じである。これまでは、実行のたびに引数で決めていた。`--stage`（1つの段階か all）と、選択式の段階を all に足すスイッチ `--frame-analysis`・`--nonlinear-analysis`（決定46・47・60）である。エディタでは、2つのチェックを利用者ごとの設定（`editor.json`）に持っていた。これらはすべて廃止する。各項目は、それが使う項目がすべて選ばれているときだけ選べる。選ばれていない項目の成果物は作り直さず、前回のものを残す。経路によって作る計算書が変わらないこと、入力を見れば何を作ったか分かることを優先した（owner 2026-10-21）。

## Considered Options

- **エディタの設定に置き、引数はいまのまま**：橋脚ごとに選べない。また、エディタと MCP・コマンドで選び方が別々になる。採らない。
- **入力に置くが、使うのは入力エディタだけ（コマンド・runner・MCP は引数のまま）**：計算に使わない値が入力に入り、経路によって意味が変わる。入力を見ても何が作られたか分からない。採らない。
- **引数（`--stage` の複数指定）で選ぶ**：同じ入力から経路ごとに違う成果物の組ができる。採らない。
- **段階の番号（0611 など）で持つ**：0611 と 0612、0800〜0820 は一緒にしか作れないので、不正な組合せを書けてしまう。画面と同じ12の単位で持つ。

## Consequences

- チェックの付け外しも入力の変更になる。入力の SHA256 が変わるので、作り直さなかった項目の前回の成果物は「今回の入力の結果ではない」と扱われる。
- `outputs` は schema 2 の必須のキーになる。ない入力、すべて false の入力、使う項目が false なのに true になっている項目のある入力は、入力エラーにする。旧形式の読み替えは作らない。
- structural-mcp の `webpier_validate`・`webpier_generate` から `stage`・`frameAnalysis`・`nonlinearAnalysis` がなくなり、`webpier_get_contract` は出力項目ごとに作れるかを返す。WebPier と structural-mcp は同じ作業で直す。
- `--addin`（ADR-0010）は作る計算書を変えないので、引数のまま残す。
